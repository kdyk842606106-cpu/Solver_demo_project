# 状态集合-活动分层网络图编辑器需求设计文档

版本：V0.2
定位：面向全流程集成场景的状态-活动网络建模与求解器输入维护工具
目标：通过可视化网络图和分层结构，提升状态、活动、依赖关系、网络深度和求解器输入数据的维护效率。

V0.2 更新重点：交互方式从固定列式二部图调整为**自由画布 + 专注画布**。用户在自由画布中自上而下建立状态节点，选择任意层级前置状态和目标状态后创建虚拟活动或原子活动；虚拟活动可进入专注画布继续分解。底层数据仍保持状态-活动-状态语义，保证求解器输入可校验，并可由现有数据库接口直接读取。

V0.2 交互更正重点：

- 画布默认且在未打开编辑会话时始终处于预览模式，只读查看；用户必须点击 `进入编辑` 后才能调整自由白板、节点、容器和连线。
- 本版本采用“打开编辑会话后统一提交”的工作方式：用户不是在白板上边改边落库，而是在编辑模式中完成一整轮画板调整，再通过 `统一提交` 一次性写入数据库；任何未进入编辑模式的页面都按预览模式处理。
- 编辑模式采用一次性提交：打开编辑会话后，所有新增、修改、删除、布局调整、覆盖刷新、同步/分叉选择只进入当前草稿，不即时写库；用户编辑完画板后点击 `统一提交`，系统才一次性校验并写入数据库。
- 状态不再按层级所有权区分本体和引用；状态本体全局唯一，状态包/容器内出现的状态本质上都是对全局状态的引用实例。
- 状态包成员引用和活动归属不使用业务连线表达，默认通过容器包含、资源树分组、面包屑、角标和属性面板显示。
- 状态包容器只包含状态引用实例；虚拟活动容器只包含子虚拟活动和原子活动，不包含状态。
- 新建状态时先自动识别重复状态，优先复用已有状态并加入当前状态包，避免创建同名同义状态。
- 画布连线只表达求解相关的状态-活动关系：`context_input`、`declared_output`、`input`、`output`。
- 折叠状态下显示摘要和聚合线，展开状态下显示局部自由布局，避免复杂网络一次性铺开。

## 1. 背景与问题

当前全流程集成建模主要存在以下问题：

- **依赖关系不直观**：状态、活动、前置条件、产出条件主要依靠数据表维护，难以整体理解网络结构。
- **建模效率低**：用户需要在多个页面之间跳转，分别维护状态、活动、前置关系和产出关系。
- **高层规划与底层执行脱节**：实际建模习惯通常是从高层流程开始拆解，但真正可执行的活动往往在第三级。如果一开始直接梳理三级活动，网络会过于复杂。
- **求解器输入数据难以维护**：求解器需要结构化、规则受控、可校验的数据，而人工维护表格容易产生孤立节点、断链、重复状态、覆盖不完整等问题。
- **缺少全局网络分析能力**：用户希望看清活动和状态的分层关系，以及它们对彼此的影响、网络分布、深度和可达性。

---

## 2. 产品定位

该编辑器不是普通流程图工具，也不是单纯的数据表前端，而是：

> **面向全流程集成场景的状态-活动分层网络建模器。**

它需要支持：

- 状态集合建模
- 活动分层建模
- 状态-活动网络编辑
- 虚拟活动辅助自上而下建模
- 可执行活动求解器输入维护
- 状态包绑定
- 局部展开与全局总览
- 模型校验
- 影响分析
- 既有数据库接口对接
- 求解器输入就绪预检

最终产物不是一张静态图，也不是独立导出文件，而是经统一提交后写入现有数据库的结构化主数据、绑定关系、覆盖快照和规则引用，供后续 planner 或求解器通过既有接口读取。

---

## 3. 适用场景

编辑器服务于全流程集成场景，包括：

- 机械装调
- 系统运行准备
- 功能验证
- 性能验证
- 维修维护序列
- 返工与拆卸序列
- 跨系统接口释放
- 跨阶段运行条件确认

典型流程：

```text
初始集成条件满足
    ↓
机械装调
    ↓
机械装调完成
    ↓
系统运行准备
    ↓
系统运行准备完成
    ↓
功能验证
    ↓
功能验证完成
    ↓
性能验证
    ↓
性能验证完成
```

## 4. 核心设计原则

### 4.1 图是主要编辑入口

编辑器不仅展示已有数据，还允许用户在进入编辑模式后直接在图上创建、连接、展开、拆分、校验状态和活动。

图编辑器采用自由画布作为主要工作区：

- 如果当前机型已经存在画布布局，则优先读取已提交布局、展开状态、节点位置和专注画布上下文。
- 如果当前机型没有画布布局，则进入空白建模态，引导用户先自上而下建立状态节点。
- 自由画布不是普通白板，所有节点和连接最终都必须通过统一提交落到结构化状态、活动、绑定和覆盖快照数据。

### 4.1.1 预览模式与编辑模式

网络编辑器默认进入预览模式。除非用户显式点击 `进入编辑` 并处于有效编辑会话中，否则页面一律按预览模式处理；首次加载、切换设备类型、刷新已提交数据、统一提交成功、取消编辑后都必须回到预览模式。

产品口径上，预览模式不是“未保存的编辑态”，而是独立的只读查看态；编辑模式也不是“自动保存态”，而是有开始、有草稿、有提交/取消的临时编辑会话。用户必须先打开编辑模式才能编辑画板，编辑完后再通过 `统一提交` 落库；如果没有打开编辑模式，页面只展示已提交数据的预览。

这是页面级状态机规则：`预览模式` 是默认状态，`编辑模式` 是显式打开的临时草稿会话。任何会改变画板、主数据、状态包成员、活动归属、绑定、覆盖快照或布局的入口，都必须同时满足“当前为编辑模式”和“当前草稿仍打开”；否则入口必须禁用、隐藏或提示先进入编辑，不能产生草稿，更不能写入数据库。

预览模式：

- 只读取已提交数据库数据和已提交画布布局。
- 支持查看、缩放、平移、展开/折叠、影响分析、求解预检和定位问题。
- 不允许创建、删除、连接、移动节点、调整容器尺寸、刷新覆盖或执行同步/分叉。
- 用户在预览模式下点击画板节点、资源树或属性面板，只能改变当前查看焦点、展开状态、筛选条件或右侧展示内容。
- 页面顶部显示 `进入编辑` 按钮。

编辑模式：

- 用户点击 `进入编辑` 后开启编辑会话。
- 编辑会话创建画布草稿，复制当前已提交状态作为草稿基线。
- 用户在编辑模式中的所有操作只修改草稿，包括主数据变更、状态包成员、活动、绑定、覆盖快照、布局、同步/分叉选择。
- 草稿中发生变更时，页面显示 `未提交更改` 状态和变更数量。
- 每一次保存抽屉、拖动节点、调整容器、拖线建绑定、刷新覆盖、同步或分叉，都只向草稿追加或合并变更；系统不得在这些单步操作后自动提交数据库。
- 用户点击 `统一提交` 后，系统一次性校验并写入数据库；结构性建模错误会阻止提交，求解准备错误会阻止求解但允许用户复核后保存建模中的图。
- 用户点击 `取消编辑` 后，丢弃本次草稿，恢复到进入编辑前的已提交状态。
- 如果用户没有进入编辑模式，或编辑模式已经因提交、取消、刷新、切换设备而结束，则不能继续使用任何画板写操作，系统只允许查看已提交结果。

统一提交：

- `统一提交` 是编辑器唯一的写库入口，提交前必须执行建模校验和求解器准备预检。
- 状态/活动层级环、引用环、唯一性冲突、分叉信息缺失等结构性问题存在时禁止提交；求解准备问题允许提交但必须展示确认提示，并在提交后继续标记为暂不可求解。
- 提交成功后，草稿成为新的已提交版本，本次编辑会话结束，页面回到预览模式。
- 提交失败时，保留草稿并显示失败原因，用户可继续修改后再次提交。

并发处理：

- 编辑会话需要记录草稿基线版本。
- 如果提交时发现数据库已被其他用户或进程更新，系统必须提示冲突。
- 冲突处理至少支持：重新载入已提交版本并放弃草稿、或查看冲突后重新提交。

### 4.2 状态和活动完全同步

状态包列表、全局状态库、活动树、网络图、属性面板共享同一份底层数据。

```text
网络图中新建状态 → 全局状态库同步出现，并可加入当前状态包
状态包列表中加入状态 → 网络图可直接显示引用实例
网络图中新建活动 → 活动树同步出现
活动树中新建子活动 → 活动画布同步可编辑
```

需要区分：

```text
数据存在 ≠ 当前画布必须显示
```

画布显示由当前视图、层级、筛选和展开状态决定。

### 4.3 状态按集合组织，活动支持分层

系统同时维护状态集合和活动分层两套结构：

```text
状态集合：描述事实、条件、结果如何被状态包聚合
活动分层：描述动作、任务、过程如何拆解
```

示例：

```text
状态包：

机械装调完成
├─ 结构装配完成
├─ 管路装配完成
└─ 电气连接完成
```

```text
活动分层：

机械装调
├─ 结构装配
├─ 管路装配
└─ 电气连接
```

状态集合和活动分层在画布上必须分开表达：

```text
状态包容器：只包含状态引用实例
虚拟活动容器：只包含活动节点
```

状态不会被放进虚拟活动容器；虚拟活动也不会被放进状态包容器。状态包不是状态的父节点，而是一个命名集合；集合成员都是对全局状态的引用实例。状态包与活动通过语义连线建立输入、输出、上下文和声明目标关系。

### 4.4 状态-活动-状态结构

所有可执行逻辑必须表达为：

```text
状态 → 活动 → 状态
```

活动依赖状态，不直接依赖活动。

### 4.5 自由画布与语义化状态-活动-状态结构

交互层采用自由画布，允许用户自由摆放状态节点、活动节点和容器节点；语义层仍遵循状态-活动-状态结构：

```text
[前置状态节点] → (活动节点) → [目标状态节点]
```

活动必须作为节点存在，不作为普通边隐藏。画布上看起来是一段从前置状态流向目标状态的箭头，但语义上拆成两类绑定：

```text
状态 → 活动：前置状态 / 上下文状态绑定
活动 → 状态：目标状态 / 声明输出绑定
```

自由画布允许用户按业务流向排布节点，但不允许产生语义不明的自由连线。任何业务连线都需要明确角色：前置、目标、上下文前置或声明输出。

状态包成员关系和活动归属不使用业务连线表达，避免用户把“在哪个状态包中出现”和“依赖谁”混在一起。它们通过以下方式显示：

- 容器包含：状态引用实例显示在状态包容器内，子活动显示在虚拟活动容器内。
- 资源树分组：左侧状态区按状态包展示成员引用，活动树显示活动层级。
- 面包屑：选中或进入节点后显示 `总画布 / 状态包或虚拟活动 / 当前节点`。
- 节点角标：状态引用实例显示 `引用`，状态包显示 `覆盖`，虚拟活动显示 `虚拟`，原子活动显示 `可执行`。
- 属性面板：展示真实状态、所在状态包、所属虚拟活动、成员数和覆盖数。

### 4.6 专注画布递归分解

虚拟活动既是当前画布中的活动节点，也是下一层专注画布的入口。

选中虚拟活动后，用户可以进入该虚拟活动的专注画布：

- 专注画布自动显示该虚拟活动声明的前置状态和目标状态，但这些状态仍属于状态体系，不进入虚拟活动容器。
- 用户可以在该范围内继续添加子虚拟活动或原子活动。
- 如果需要新增或引用状态，状态仍创建在状态包容器或状态区域中，再通过语义连线与活动建立关系。
- 每一层都重复同样的“选择前置状态 → 选择目标状态 → 创建活动 → 校验覆盖”流程。
- 专注画布中的内部活动必须最终实现父虚拟活动声明的目标状态覆盖。

## 5. 核心概念

### 5.1 状态 State

状态表示某个事实、条件或结果已经成立。

示例：

- 左侧管路完成
- 系统运行准备完成
- 安全条件满足
- 功能验证通过
- 接口A释放

状态可作为活动的前置，也可作为活动的产出。

### 5.2 全局状态库与状态包

状态本体进入全局状态库，不直接携带层级所有权或主归属关系。

状态包是一个命名状态集合，用于表达业务阶段、目标状态或上下文条件。状态包内的每个成员都是对全局状态的引用实例，而不是该状态的子对象。

```text
状态包 = AND(当前成员状态引用)
```

即状态包内当前成员状态全部达成后，该状态包才算达成。状态包可以作为活动的前置、上下文前置、声明输出或目标状态使用。

### 5.3 状态引用实例

同一个真实状态可以出现在多个状态包中。所有出现位置都是引用实例，不再维护所谓主归属实例。

示例：

```text
接口A释放
├─ 出现在状态包：系统运行准备完成
└─ 出现在状态包：功能验证条件满足
```

画布和资源树显示的是引用实例：

```text
接口A释放  引用
所在状态包：系统运行准备完成
```

同一个状态出现在多个状态包时，底层仍只维护一个真实状态对象。

状态引用默认不在画布上画引用连线。引用实例通过容器位置、`引用` 角标、资源树分组和右侧属性面板显示。

每个出现位置都应作为独立引用实例保存显示信息。用户在某个状态包容器内拖动该引用实例时，只更新该引用实例的布局 metadata，不改变真实状态本体，也不影响同一真实状态在其他状态包中的位置。

当画布聚焦到某个状态包或展开该状态包容器时，指向该真实状态的状态-活动语义连线应优先连接到当前状态包内的引用实例端点；底层绑定仍按真实状态本体保存。这样用户看到的连线端点与当前容器内的实例位置一致，同时不改变求解器读取的 canonical 状态 ID。

删除引用实例只移除该状态在当前状态包中的成员关系，不删除真实状态。

### 5.4 重复状态识别

用户新建状态时，系统必须自动识别重复状态，避免创建同名同义状态。

重复识别至少应包含：

- 编码完全相同。
- 名称在同一设备类型下完全相同。
- 原子状态的 `feature_key + operator + target_value` 完全相同。
- 名称相似但编码不同的潜在重复项。

处理规则：

- 如果存在唯一确定的重复状态，默认复用已有状态，并把它加入当前状态包。
- 如果存在多个候选重复状态，弹出候选列表，用户选择复用哪一个，或明确选择“仍然新建”。
- 如果用户输入的是全新状态，则创建新的全局状态对象，再在当前状态包中创建引用实例。
- 重复识别结果要在保存前显示，例如 `已发现相同状态，将复用：接口A释放`。

### 5.5 状态包绑定 State Package Binding

当活动绑定状态包时，系统解释为绑定该状态包当前覆盖范围内的成员状态。

示例：

```text
活动A → 机械装调完成[状态包]
```

如果“机械装调完成”状态包包含：

```text
机械装调完成
├─ 结构装配完成
├─ 管路装配完成
└─ 电气连接完成
```

则该绑定表示活动A产出该状态包覆盖范围内的成员状态。

### 5.6 状态包覆盖快照

状态包绑定需要记录覆盖快照。状态包新增成员引用后，原有活动不自动覆盖新增成员。

示例：

```text
活动A → 机械装调完成[状态包 3/4]
```

表示该活动只覆盖当前状态包中 4 个成员状态里的 3 个。

系统需要提示：

```text
状态包新增了 1 个成员状态。
活动A当前未覆盖该状态。
请确认是否扩展覆盖范围。
```

### 5.7 活动 Activity

活动表示状态变化的动作。

```text
前置状态 → 活动 → 产出状态
```

活动可以有多个前置状态，也可以有多个产出状态。

### 5.8 虚拟活动 Virtual Activity

虚拟活动用于辅助自上而下建模，是活动分层中的高层活动。

特点：

- 用于组织、展示、分解和压缩复杂网络
- 可以声明输入状态包和输出状态包
- 可以设置上下文前置条件
- 可以包含内部子活动
- 展开为容器时只包含子虚拟活动和原子活动，不包含状态节点
- 不参与求解器计算

示例：

```text
(V) 机械装调
(V) 系统运行准备
(V) 功能验证
(V) 性能验证
```

### 5.9 可执行活动 Executable Activity

可执行活动是真正参与求解器计算的活动。

当前约定：

```text
三级活动才是真正可执行活动
```

示例：

```text
(E) 安装左侧管路
(E) 完成上电前检查
(E) 加载控制软件
(E) 执行功能点A验证
(E) 拆卸局部管路
```

### 5.10 上下文前置条件

虚拟活动可以设置上下文前置条件，并继承给内部可执行活动。

示例：

```text
(V) 功能验证
上下文前置：
- 系统运行准备完成[状态包]
- 安全条件满足[状态包]
- 测试设备就绪[状态包]
```

内部活动默认继承这些前置条件。

求解器读取数据库时：

```text
真实前置 = 继承前置 + 自身前置
```

## 6. 主要使用流程

### 6.0 成品页面操作流总览（自由白板版本）

用户打开 `数据管理 / 网络编辑器` 后，成品页面默认是预览态，不直接编辑数据库。成品页面只有两种工作状态：未点击 `进入编辑` 时一律是预览模式；点击 `进入编辑` 后才进入临时编辑会话，编辑完画板后通过顶部 `统一提交` 一次性写入数据库。抽屉里的 `保存`、画板上的拖拽、端口连线、容器调整、自动整理、覆盖刷新和同步/分叉选择都只是把变更加入本次草稿，不代表数据库已经更新。

页面区域从上到下、从左到右分为：

- 顶部工具栏：显示设备类型选择、`预览模式 / 编辑模式` 状态、`进入编辑`、`统一提交`、`取消编辑`、`自动整理`、`校验`、`影响分析`、`求解预检`；设备类型选择器应保留搜索，并按最近使用、业务设备类型、测试 / 样例设备类型分组，降低测试数据噪声。
- 左侧资源区：显示状态包 / 状态库、活动树、未布置节点、搜索筛选和 `编辑草稿` 列表。
- 中间 X6 单画布：只保留一张可缩放、可平移的大画布，显示状态节点、状态引用实例、状态包容器、虚拟活动容器、原子活动节点和状态-活动语义连线；不再拆成左右两个图，也不再把状态包或虚拟活动画成“普通节点 + 外框”两套对象。
- 右侧属性区：显示当前选中节点、绑定、覆盖、同步/分叉影响、重复状态候选、影响分析和建议操作。
- 底部校验区：显示阻塞问题、提示问题和可定位的问题列表。

工作区应有明确的内部滚动边界：左侧资源区、右侧属性区、底部校验 / 求解预检区各自滚动，画布在中间区域内伸缩。低高度屏幕下不应要求用户依赖整页盲滚才能找到右侧属性或底部问题列表。

X6 单画布原则：

1. X6 是画布交互引擎，只负责节点、容器、端口、边、缩放、平移、选择、拖拽和基础命中；重复状态识别、共享状态包同步 / 分叉、求解预检和一次性提交仍由现有业务层负责。
2. 后端协议保持不变：图数据仍来自 `network-editor/graph`，所有画板语义和布局变更仍先进入 `draftChanges`，最终只通过 `network-editor/commit` 统一写库；求解器仍通过 `network-editor/solver-precheck` 和既有数据库接口读取已提交数据。
3. 画布适配层把后端状态、状态引用、虚拟活动、原子活动和绑定投影为 X6 cells；实现层至少拆分为 graph adapter、cell factory、container projection、edge projection 和 draft bridge，避免把业务规则散落在 X6 事件回调里。
4. 子节点布局继续按画布绝对坐标保存到 `_network_editor_layout`，容器尺寸继续保存到 `_network_editor_container`；本轮不把数据库布局迁移为容器相对坐标。
5. 展开 / 折叠是查看状态，不直接写库；只有拖动节点、调整容器尺寸、创建或删除连线、刷新覆盖、修改属性、同步 / 分叉选择等编辑动作才进入草稿。

预览模式下：

1. 顶部状态显示 `预览模式`，主操作按钮为 `进入编辑`。
2. 中间白板读取已提交布局，节点可选中、定位、展开、折叠、查看影响路径，但不显示可拖动布局手柄。
3. 左侧可以搜索和定位状态或活动，不能新建、删除、移动、刷新覆盖、同步/分叉或连线。
4. 右侧属性区只显示已提交数据、覆盖结果和影响分析，不允许保存修改。
5. 点击 `求解预检` 时，页面展示求解器准备摘要、阻塞项、候选活动和请求模板摘要；不下载 JSON，不生成离线数据包，求解器后续通过既有数据库接口读取已提交数据。若切换到 `求解` 视图，画布顶部应提示“仅显示可执行活动与求解事实投影”，避免用户误以为虚拟活动消失是错误。若预检为 `blocked`，请求模板摘要必须标明“仅预检摘要”并显示阻塞项数量，不得被误认为可直接调用求解器的输入。
6. 切换设备类型、重新进入页面、取消编辑或统一提交成功后，页面都回到该模式；此时即使之前打开过抽屉或选中过节点，也不能继续沿用旧草稿修改画板。

进入编辑模式：

1. 用户点击顶部 `进入编辑`。
2. 顶部状态切换为 `编辑模式`，显示未提交变更数量。
3. 左侧出现 `编辑草稿` 列表；所有新增、修改、删除、布局移动、容器调整、状态包成员变化、活动归属变化、绑定变化、覆盖刷新、同步/分叉选择都会先加入草稿。
4. 中间 X6 单画布节点显示布局手柄或语义端口，用户可以拖动节点、连接状态与活动、展开容器并调整容器内部节点位置。
5. 右侧属性面板的保存按钮只把修改写入草稿，不立即写数据库。
6. 用户编辑完画板后点击顶部 `统一提交`。这是本轮编辑唯一写库动作；系统一次性执行重复检查、结构校验、求解器准备校验、覆盖快照检查和同步/分叉确认，再把草稿写入现有数据库表或已有接口承接的数据结构。
7. 如果提交成功，页面回到预览模式并重新读取已提交数据。
8. 如果提交失败，页面停留在编辑模式，草稿保留，底部和右侧显示失败原因。
9. 用户点击 `取消编辑` 时，系统提示将丢弃草稿；确认后回到预览模式并恢复已提交数据。

自由白板操作：

1. 用户在编辑模式中把鼠标移到节点左侧布局手柄。
2. 按住布局手柄拖动节点到任意空白位置。
3. 松开鼠标后，节点位置变化加入 `编辑草稿`，左侧草稿列表显示 `调整位置` 类变更。
4. 状态包折叠时是一个高层状态节点；点击展开后，同一个高层对象切换为状态包容器，内部成员状态引用实例显示在容器内并可自由摆放；状态包整体移动时，内部相对坐标保持不变。
5. 虚拟活动折叠时是一个虚拟活动节点；点击展开后，同一个虚拟活动切换为容器，内部只显示子虚拟活动和原子活动，用户可以自由摆放这些活动节点；状态节点不能放进虚拟活动容器。
6. X6 画布支持查看缩放和平移：用户可点击画布动作条的缩小、百分比重置、放大控件，也可按住 `Ctrl` 或 `Alt` 滚轮缩放；缩放和平移只改变查看状态，不进入编辑草稿、不写库。
7. 自动整理只能作为显式操作，不能无提示覆盖用户手动摆放的位置。

新增状态：

1. 用户选中状态包容器或左侧状态包条目，点击 `添加状态`。
2. 系统打开状态编辑抽屉，用户填写名称、编码、状态类型、特征和值。
3. 保存前系统自动识别重复状态。
4. 如果唯一命中已有状态，系统提示 `已发现相同状态，将复用`，并把该真实状态作为引用实例加入当前状态包。
5. 如果命中多个候选，右侧或弹窗展示候选列表，用户选择复用某一项或明确选择仍然新建。
6. 如果没有重复，系统创建新的全局状态对象，并在当前状态包下创建成员引用实例。
7. 如果当前状态包已展开，新成员默认落在容器内部空白位置；如果折叠，只更新状态包摘要。
8. 以上结果都先进入草稿，只有点击 `统一提交` 后才写入数据库。

被多个高级状态包引用的状态包发生成员修改时：

1. 用户在某个状态包上下文中添加、移除或替换成员状态。
2. 系统检测该状态包已被多个高级状态包引用，弹出 `同步 / 分叉` 决策。
3. 选择 `同步到共享状态包`：本次成员变化作用于原状态包，所有引用该状态包的高级状态包都看到变化；相关覆盖快照重新计算为 `complete`、`partial` 或 `stale`，影响范围进入草稿。
4. 选择 `分叉当前状态包`：系统复制原状态包的成员引用列表，创建新的状态包分支；当前上下文改用新分支，新增状态只进入新分支，其他引用方保持原状态包不变；用户必须填写分支名称和分支说明。
5. 同步或分叉选择本身也进入草稿；提交前右侧影响面板必须列出受影响状态包、绑定和覆盖缺口。

连线操作：

1. 状态包成员关系和活动归属不画业务线，不通过连线维护。
2. 画布连线只表达求解相关的状态-活动语义。
3. 状态右侧端口拖到虚拟活动左侧端口，创建 `context_input`。
4. 虚拟活动右侧端口拖到状态左侧端口，创建 `declared_output`。
5. 状态右侧端口拖到原子活动左侧端口，创建 `input`。
6. 原子活动右侧端口拖到状态左侧端口，创建 `output`。
7. 松手后系统显示角色、端点、覆盖范围和规则选择；如果绑定的是多叶子状态包，确认框提供 `全部当前成员` 和 `选择部分成员`，选择部分成员时只预填右侧表单，用户勾选叶子状态后再点击 `连接`。
8. 右侧 `创建绑定` 表单在状态包绑定场景显示覆盖范围选择：`全部当前成员` 不提交显式叶子状态列表，由后端按当前启用叶子状态生成完整快照；`选择部分成员` 必须至少勾选一个叶子状态，并把所选 `covered_leaf_state_ids` 随绑定草稿提交。
9. 批量绑定默认使用每个状态包的全部当前 active 叶子；如果需要 partial 覆盖，用户应使用单条绑定表单创建或更新。
10. 高层节点折叠时，内部隐藏节点相关连线重定向到容器边界并显示聚合线和摘要；展开容器、选中节点、打开覆盖详情或进入实现 / 求解视图时再展开具体端点，避免画面过乱。

### 6.1 进入画布

用户进入网络编辑器后，系统按以下规则初始化画布：

1. 如果该机型存在已保存画布，则读取已有画布布局、节点位置、展开/收起状态、当前专注画布和筛选条件。
2. 如果该机型没有画布，则进入空白自由画布，提示用户先建立高层状态。
3. 画布不采用固定左右列布局，状态、活动、容器和语义线都位于同一张 X6 大画布中；节点可自由摆放，系统提供自动整理能力，避免节点重叠和连线错位。
4. 用户可以从左侧状态包列表、全局状态库、活动树或画布直接定位节点。

### 6.2 自上而下建立状态包和状态引用

用户先在自由画布中建立高层状态包，形成业务阶段和目标状态框架：

```text
[初始集成条件满足 状态包]
[机械装调完成 状态包]
[系统运行准备完成 状态包]
[功能验证完成 状态包]
```

状态包可以从画布中新建，也可以从左侧状态包列表拖入。展开状态包后，该高层节点本身切换为容器形态，内部显示成员状态引用实例，不再额外保留一个普通状态包节点。

展开后的状态包容器内部仍然是自由布局区域，用户可以拖动成员状态引用实例调整位置。状态包容器整体移动时，内部引用实例跟随移动；状态包折叠后隐藏内部实例，再次展开时恢复上一次局部坐标。

### 6.3 状态包成员维护与重复识别

用户在状态包中维护成员状态：

```text
机械装调完成
├─ 结构装配完成
├─ 管路装配完成
└─ 电气连接完成
```

原高层绑定不被破坏：

```text
(V) 机械装调 → 机械装调完成[状态包]
```

系统记录并显示覆盖范围。

状态包中的每一项都是全局状态的引用实例。同一个状态允许出现在不同状态包下：

- 如果系统识别出同一个真实状态，应复用已有状态并创建引用实例，不重复创建真实状态。
- 引用实例在画布上显示为同名状态的一个实例，保留 `引用` 角标和所在状态包信息。
- 删除实例只删除该状态在当前状态包中的成员关系，不删除真实状态。

状态包成员维护入口在状态包节点上：

```text
状态包节点菜单：
- 添加状态
- 引用已有状态
- 展开 / 折叠
- 查看覆盖
```

用户点击 `添加状态` 后，系统先按编码、名称、`feature_key + operator + target_value` 自动识别重复状态。如果存在唯一匹配项，系统默认复用已有状态并把它加入当前状态包；如果存在多个候选项，弹出候选列表让用户选择复用或明确新建。保存到草稿后，成员状态引用实例默认落在该状态包容器内部的空白位置；如果状态包当前折叠，只更新节点摘要，例如 `成员 2 → 3`。只有点击 `统一提交` 后，该成员关系才写入数据库。

用户点击 `引用已有状态` 后，选择已有状态，系统在当前草稿的状态包容器内创建引用实例，并在节点和右侧属性面板中显示真实状态与所在状态包。

### 6.4 被引用状态包的同步/分叉决策

当用户修改一个已经被其他状态包引用的状态包成员时，系统不能静默传播，也不能静默只改当前视图，必须让用户明确选择“同步”或“分叉”。

触发场景包括：

- 向被引用状态包新增成员状态。
- 从被引用状态包移除成员状态。
- 批量替换被引用状态包的成员状态。

弹窗需要显示影响范围：

```text
状态包「模块装配完成」已被以下状态包引用：
- 机械装调完成
- 交付准备完成

你正在新增成员状态「模块C已安装」。
请选择处理方式：
[同步到共享状态包] [分叉当前状态包]
```

选择 `同步到共享状态包` 时：

1. 修改直接落到原状态包。
2. 所有引用该状态包的高级状态包都会看到成员变化。
3. 受影响的活动-状态包绑定覆盖快照重新计算为 `complete`、`partial` 或 `stale`。
4. 系统在影响分析中列出所有受影响状态包和绑定。

选择 `分叉当前状态包` 时：

1. 系统复制原状态包的成员引用列表，创建一个新的状态包分支。
2. 新分支复用同一批全局状态对象，不复制状态本体。
3. 当前编辑上下文改为引用新状态包分支。
4. 原状态包及其他引用方保持不变。
5. 新状态只加入新分支。
6. 系统必须要求用户填写或确认分支说明，例如：

```text
分支名称：模块装配完成 - 机械装调用
分支说明：机械装调场景需要额外确认模块C安装状态，交付准备仍沿用原模块装配完成定义。
```

分叉后的状态包需要在 UI 中显示来源：

```text
模块装配完成 - 机械装调用
来源：模块装配完成
分叉原因：机械装调场景需要额外确认模块C安装状态
```

默认推荐项：

- 如果用户从“共享状态包定义维护”入口进入，默认推荐 `同步到共享状态包`。
- 如果用户从某个高级状态包或专注画布上下文中修改，默认推荐 `分叉当前状态包`。

### 6.5 创建活动：选择前置状态与目标状态

用户通过活动创建向导创建虚拟活动或原子活动。

推荐交互：

1. 点击或通过快捷菜单选择“新建虚拟活动”或“新建原子活动”。
2. 系统进入“选择前置状态”阶段。
   - 用户可以在画布中单选或多选状态引用实例或状态包。
   - 用户也可以在状态包列表中单选或多选状态包、成员状态。
   - 选择状态包时，系统按状态包处理，并生成覆盖快照。
3. 点击“选择目标状态”后，系统进入目标状态选择阶段。
   - 用户继续在画布或状态包列表中单选或多选状态包、成员状态。
   - 目标状态可以是已有状态，也可以在当前步骤中新建。
4. 点击“确认”后，弹出活动信息编辑面板。
5. 用户填写活动名称、编码、类型、所属虚拟活动、规则信息等。
6. 保存到草稿后，系统在画布中创建活动节点，并生成状态-活动-状态连接；点击 `统一提交` 后才写入数据库。

创建结果示例：

```text
[初始集成条件满足] ──▶ (V) 机械装调 ──▶ [机械装调完成]
```

如果创建的是虚拟活动：

```text
前置状态 → 虚拟活动：context_input
虚拟活动 → 目标状态：declared_output
```

如果创建的是原子活动：

```text
前置状态 → 原子活动：input / op_rule precondition
原子活动 → 目标状态：output / op_rule effect
```

原子活动创建与规则生成：

- 新建原子活动面板允许用户一次选择多个前置状态和多个产出状态。
- 保存时不立即写库，而是同批次进入编辑草稿：先生成原子活动草稿，再生成 `input/output` 绑定草稿；如果产出状态可转换为 effect fact，再同批生成默认 `op_rule` 草稿。
- 默认 `op_rule` 必须通过草稿引用指向同批创建的原子活动；`input/output` 绑定也通过草稿引用指向该原子活动，并在有默认规则时指向该规则，统一提交时再解析为真实 ID。
- 产出状态至少需要包含一个可转成 effect 的原子状态事实，系统才自动生成规则；如果暂时无法转换，允许按“待补规则”保存原子活动和两侧绑定，求解器准备校验必须阻塞。
- 如果用户选择状态包作为前置或产出，画布只保留到该状态包的一条语义绑定，规则 facts 则展开到覆盖范围内的 active 叶子原子状态，避免在自由白板上生成大量叶子连线。
- 原子活动产出多叶子状态包时，保存前必须显示覆盖范围选择：`全部当前成员` 按当前 active 叶子生成完整 output 快照和 effect facts；`选择部分成员` 要求至少勾选一个叶子状态，并只为所选叶子生成 output 覆盖快照和 effect facts；用户也可以取消抽屉放弃本次草稿。
- 统一提交成功后，原子活动、可选规则、绑定一起落入现有数据库；结构性错误、唯一性冲突或草稿引用解析失败时整批回滚并保留草稿。

### 6.6 虚拟活动专注画布细化

用户选中虚拟活动后，可以点击“添加虚拟活动”“添加原子活动”或双击进入专注画布。

进入专注画布时：

- 虚拟活动节点本身提供 `专注` 入口，双击节点也进入同一个专注上下文。
- 顶部显示父虚拟活动面包屑、上下文前置状态、声明输出状态和实现覆盖摘要。
- 如果当前虚拟活动有父虚拟活动，顶部提供 `上层`；如果用户要回到全局画布，点击 `退出` 清空 activity scope。
- 画布显示该虚拟活动声明的前置状态和目标状态，作为状态体系中的边界状态。
- 虚拟活动容器内部只显示子虚拟活动和原子活动。
- 前置状态和目标状态可作为容器外部边界节点固定在画布两侧，或由自动布局放置在活动容器外部。
- 用户可以继续添加子虚拟活动和原子活动，并自由调整这些活动在虚拟活动容器内部的位置。
- 如需新增中间状态或引用已有状态，应在状态包容器或状态区域中维护，再与容器内活动建立 `input/output` 连线。
- 专注画布中的新增子虚拟活动、原子活动、绑定和布局调整仍然先进入编辑草稿，点击 `统一提交` 后才写入数据库。

专注画布内部示例：

```text
[初始集成条件满足]      ┌ (V) 机械装调 ───────────┐      [机械装调完成]
                         │ (V) 结构装配            │
                         │ (E) 安装模块A           │
                         │ (E) 安装模块B           │
                         └─────────────────────────┘

[安全条件满足] ──▶ (E) 安装模块A ──▶ [模块A已安装]
```

专注画布不是独立模型。它保存的是父虚拟活动内部的子活动、绑定关系和布局上下文；状态仍由状态体系维护，虚拟活动容器只负责活动归属与活动内部布局。

### 6.7 原子活动收敛与合规

用户重复虚拟活动分解过程，直到所有需要被实现的目标状态都由原子活动产出，且所有原子活动具备合规前置、目标状态和可用规则。

目标完成条件：

- 每个需要求解的成员状态都有可追溯的原子活动产出，或被明确标记为初始状态/外部输入。
- 每个原子活动至少有一个前置状态和一个目标状态。
- 每个原子活动绑定明确的 active `op_rule`。
- 虚拟活动声明的目标状态被内部原子活动完整实现。
- 状态包覆盖快照不存在 stale 或 partial 缺口，或缺口被用户明确接受为非求解范围。

### 6.8 实现完整性校验

系统检查虚拟活动声明的目标状态包是否被内部可执行活动完整实现。

示例：

```text
(V) 机械装调

声明输出：
- 机械装调完成[状态包]

状态包包含：
- 结构装配完成
- 管路装配完成
- 电气连接完成

内部活动已产出：
- 结构装配完成
- 管路装配完成
```

校验结果：

```text
实现状态：部分实现 2/3
缺失状态：电气连接完成
```

### 6.9 求解器准备

进入求解器准备模式时：

- 隐藏虚拟活动
- 只显示可执行活动
- 展开状态包绑定
- 检查状态覆盖完整性
- 检查孤立节点
- 检查循环依赖
- 检查不可达状态

求解器通过既有数据库接口读取可执行活动及其状态绑定关系；虚拟活动只作为 group / WBS / display metadata 保留，不作为求解活动。

### 6.10 展开、折叠与容器布局流程

用户在自由画布中可以对状态包和虚拟活动执行展开、折叠和整理。

状态包展开流程：

1. 用户点击状态包节点右上角 `展开`。
2. 状态包变成容器，内部显示成员状态引用实例。
3. 用户可自由拖动容器内部状态引用实例，也可拖动容器右下角调整容器尺寸。
4. 用户点击 `添加状态`，系统先做重复识别，再决定复用已有状态或创建新状态；点击 `引用已有状态`，直接选择已有状态加入当前状态包。
5. 用户点击 `折叠`，内部节点隐藏，状态包节点显示 `成员`、`覆盖`、`关联活动` 等摘要。
6. 再次展开时，恢复上次保存的容器尺寸和内部节点局部坐标。

虚拟活动展开流程：

1. 用户点击虚拟活动节点右上角 `展开`。
2. 虚拟活动变成活动容器，内部只显示子虚拟活动和原子活动。
3. 用户可自由拖动容器内部活动节点，也可调整容器尺寸。
4. 用户点击 `添加子虚拟活动` 或 `添加原子活动`，新活动默认落在容器内部空白处。
5. 用户点击 `折叠`，内部活动隐藏，虚拟活动节点显示 `子活动`、`输出实现`、`上下文`、`阻塞` 等摘要。
6. 再次展开时，恢复上次保存的容器尺寸和内部活动局部坐标。

状态包容器和虚拟活动容器的内部布局互不混用：状态包容器只放状态引用实例，虚拟活动容器只放活动。

### 6.11 状态包成员与活动归属操作流

状态包成员关系和活动归属不通过主画布业务线维护。

状态包成员关系：

1. 用户选中状态包。
2. 点击节点菜单 `添加状态`。
3. 系统自动识别重复状态；唯一命中时复用已有状态，多候选时让用户选择，未命中时创建新状态。
4. 系统把最终状态作为成员引用加入当前状态包，并在左侧状态包列表中同步显示。
5. 如果状态包展开，成员引用实例出现在容器内部；如果状态包折叠，只更新状态包摘要。

引用已有状态：

1. 用户选中目标状态包。
2. 点击节点菜单 `引用已有状态`。
3. 系统弹出已有状态选择器。
4. 保存到草稿后，在当前状态包容器内出现引用实例，节点带 `引用` 角标。
5. 右侧属性面板显示真实状态、所在状态包和是否被其他状态包复用。
6. 删除时按钮文案必须是 `移出状态包` 或 `移除引用`，不能使用容易误解为删除真实状态的文案。

活动归属关系：

1. 用户选中虚拟活动。
2. 点击 `添加子虚拟活动` 或 `添加原子活动`。
3. 系统在该虚拟活动下创建子活动，并在左侧活动树同步显示缩进层级。
4. 如果虚拟活动容器展开，新活动出现在容器内部；如果折叠，只更新父虚拟活动摘要。

### 6.12 连线创建与显示流程

连线创建有两种入口：拖线和选择式创建。

拖线流程：

1. 用户把鼠标移到节点语义端口，端口高亮。
2. 从状态右侧端口拖到活动左侧端口，创建 `context_input` 或 `input`。
3. 从活动右侧端口拖到状态左侧端口，创建 `declared_output` 或 `output`。
4. 松手后系统弹出角色确认，显示起点、终点、角色、覆盖范围和规则选择。
5. 用户确认后生成业务绑定和画布边。

选择式创建流程：

1. 用户先点击顶部 `进入编辑`。未进入编辑时，画布处于预览模式，状态多选只允许查看和定位，不允许创建活动。
2. 用户按住 `Ctrl` / `Shift` / `Cmd` 点击一个或多个状态节点，节点出现多选高亮，画布上方浮出 `已选 / 前置 / 产出` 操作条。
3. 用户点击 `设为前置`，系统把当前多选批次标记为前置状态，并用前置样式提示这些状态已暂存。
4. 用户再按住 `Ctrl` / `Shift` / `Cmd` 多选一个或多个目标状态，点击 `设为产出`，系统把当前批次标记为目标状态，并用产出样式提示这些状态已暂存。
5. 操作条显示 `创建虚拟活动`、`创建原子活动`。点击 `创建虚拟活动` 时，系统打开虚拟活动抽屉并预填上下文输入和声明输出；点击 `创建原子活动` 时，系统打开原子活动抽屉并预填输入状态和产出状态。
6. 用户填写活动名称、编码、说明、所属活动包、规则时长或覆盖范围等必要信息后点击保存。
7. 系统只把活动节点和两侧语义连线加入编辑草稿，不直接写数据库。用户继续编辑画板或点击顶部 `统一提交` 后，草稿才一次性落到现有数据库接口。

显示流程：

- 默认显示当前层级主线。
- 折叠状态包和虚拟活动时显示聚合线与摘要。
- 选中节点时展开相关线并高亮影响路径。
- 输入或输出数量过多时先显示汇总线，点击后再展开详情。

## 7. 页面结构

推荐布局：

```text
┌────────────────────────────────────────────────────────────┐
│ 顶部工具栏：进入编辑 / 统一提交 / 取消编辑 / 自动整理 / 校验 / 影响分析 / 求解预检 │
├───────────────┬───────────────────────────┬────────────────┤
│ 左侧资源树      │ 中间自由画布                 │ 右侧属性面板      │
│               │                           │                │
│ 状态包 / 状态库  │ 状态节点 + 活动节点            │ 状态属性          │
│ 活动树          │ 状态包容器 + 虚拟活动容器        │ 活动属性          │
│ 引用状态        │ 专注画布 / 局部展开             │ 状态包覆盖范围     │
│ 未布置节点      │ 影响路径高亮                  │ 继承前置条件       │
│ 搜索/筛选       │ 自动布局 / 平滑曲线             │ 校验问题          │
├───────────────┴───────────────────────────┴────────────────┤
│ 底部校验区：未实现虚拟活动 / 状态包覆盖缺口 / 循环 / 孤立节点       │
└────────────────────────────────────────────────────────────┘
```

交互不应全部依赖固定按钮。除顶部工具栏外，需要提供：

- 节点悬浮快捷操作：状态节点至少提供 `编辑`，状态包节点提供 `添加状态`；虚拟活动节点提供 `进入专注画布`、`添加内部活动` 或 `添加原子活动`。
- 右键或更多菜单：右键状态或活动节点时显示节点菜单，提供聚焦、编辑和当前节点可用的内部新增入口；预览模式下只保留查看/聚焦类动作，写操作禁用。
- 多选后的浮动操作条：仅编辑模式显示；位置靠近当前多选状态组上方，展示 `已选`、`前置`、`产出` 数量，并提供 `设为前置`、`设为产出`、`创建虚拟活动`、`创建原子活动`、`清空`。已标记为前置或产出的状态节点应有可区分的视觉提示，避免用户只靠线条判断语义。
- 画布任意空白位置双击快速新建状态；若双击位置位于展开状态包容器内部，新状态默认挂到该状态包下，并把双击坐标作为初始布局草稿。
- 虚拟活动节点上的“进入专注画布”“添加内部活动”入口。
- 校验问题中的定位和一键修复入口。

页面默认和非编辑会话一律是预览模式。预览模式下，创建、删除、移动、连线、覆盖刷新、同步/分叉、状态多选创建活动等入口必须禁用或隐藏，只保留查看、定位、展开/折叠、影响分析、校验和求解预检。用户点击顶部 `进入编辑` 后才打开临时草稿并显示会修改草稿的操作；点击 `统一提交` 成功、`取消编辑`、刷新已提交数据或切换设备类型后，都必须结束编辑会话并回到预览模式。

一次性提交是页面级硬约束：`进入编辑` 只表示打开本次画板编辑会话，不直接写库；抽屉保存、节点拖动、容器尺寸调整、端口连线、自动整理、覆盖刷新、状态包同步/分叉选择等所有写操作都只能先进入编辑草稿。`统一提交` 是唯一调用现有数据库写入接口的动作；提交成功后草稿成为已提交数据并回到预览模式；提交失败或用户在提交前复核中取消时，草稿保留在当前编辑会话内；用户点击 `取消编辑` 并确认 `丢弃草稿` 时，草稿必须被丢弃并回到预览模式。预览模式中的展开/折叠、聚焦、影响分析、校验和求解预检只改变查看上下文或读取已提交数据，不创建草稿，也不产生未提交变更。

画布连线区域只承载状态-活动依赖关系。状态包成员关系和活动归属通过左侧列表、画布容器、面包屑和右侧属性展示，不在主画布中画成业务线。

## 8. 主要视图模式

### 8.1 纲要建模模式

用于自上而下快速梳理状态、目标和高层虚拟活动。

显示：

- 高层状态
- 虚拟活动
- 状态包绑定
- 主流程关系
- 自由画布布局
- 节点展开/收起状态

允许存在：

- 未分解虚拟活动
- 未完全实现状态包
- 未细化状态

但需要标记模型暂不可求解。

### 8.2 详细实现模式

用于在当前画布或专注画布中继续分解虚拟活动，建立可执行活动网络。

显示：

- 虚拟活动容器
- 内部可执行活动
- 状态包容器和状态节点
- 继承前置条件
- 自身前置条件
- 产出状态

虚拟活动容器内部只显示活动。状态引用实例即使与容器内原子活动相连，也应显示在状态包容器或状态区域中，不能作为虚拟活动容器的子节点。

### 8.3 专注画布模式

用于进入某个虚拟活动内部，集中维护该虚拟活动的内部活动、状态绑定和实现覆盖。

显示：

- 父虚拟活动名称和面包屑路径
- 父虚拟活动声明的前置状态
- 父虚拟活动声明的目标状态
- 内部虚拟活动
- 内部原子活动
- 内部实现覆盖情况

专注画布允许继续进入下一级虚拟活动，形成递归下钻。

父虚拟活动声明的前置状态和目标状态是专注画布的边界状态，不属于虚拟活动容器。专注画布中的虚拟活动容器仍然只包含活动；如需新增或引用状态，应通过状态包容器、全局状态库或状态区域维护。

### 8.4 求解器准备模式

用于检查求解器输入是否已在数据库中准备就绪。

显示：

- 可执行活动
- 真实前置状态
- 真实产出状态
- 状态包展开结果
- 聚合状态关系
- 校验问题

隐藏或弱化：

- 虚拟活动
- 展示性连接
- 纲要层辅助结构

## 9. 展示与交互规则

### 9.0 自由画布视觉与布局规则

画布应以“业务流向清晰、节点不重叠、空间利用紧凑”为核心目标。

基础要求：

- 节点可以自由拖拽，但系统应提供自动布局和一键整理。
- 自动布局需要避免节点重叠，尽量减少连线交叉。
- 节点形状应小巧、易懂，不浪费大量留白。
- 前置状态到活动、活动到目标状态的箭头起止点必须准确连接到节点边界或预定义连接点。
- 连线使用平滑曲线，避免折线穿过节点主体。
- 多条线连接同一节点时，需要自动错开端口或曲线，避免完全重叠。
- 展开状态包后，状态包变为容器，成员状态引用实例在容器内部可自由摆放；系统可提供自动整理，但不能强制覆盖用户手动布局。
- 收起状态包后，外部连线连接到状态包容器边界。
- 用户手动移动后的节点位置需要保存为画布布局；自动布局不能无提示覆盖用户手动整理结果。
- 状态包成员关系和活动归属不画业务连线，不占用状态-活动依赖连线通道。
- 状态包容器和虚拟活动容器都支持拖拽调整尺寸；容器变大或移动时，内部节点的相对局部坐标保持不变。

视觉建议：

```text
[前置状态] ──╮
             ╰──▶ (活动节点) ──▶ [目标状态]
[前置状态] ──╯
```

活动节点需要与状态节点有明显区分：

- 状态节点：矩形或圆角矩形，强调事实/条件/结果。
- 虚拟活动：胶囊、六边形或带 V 标识的节点，强调可继续分解。
- 原子活动：小型实心活动节点或带 E 标识的节点，强调可执行。
- 状态引用实例：使用 `引用` 角标或成员标记说明它是全局状态在当前状态包中的一次出现。

### 9.1 状态节点形态

状态节点和状态包至少支持以下形态：

1. **真实状态**

```text
左侧上部管路完成
```

2. **折叠状态包**

```text
机械装调完成
成员：3
覆盖：3/4
关联活动：8
```

3. **展开状态包容器**

```text
┌──────────── 机械装调完成 ────────────┐
│ 结构装配完成                          │
│ 管路装配完成                          │
│ 电气连接完成                          │
└─────────────────────────────────────┘
```

4. **状态引用实例**

```text
接口A释放 [引用]
```

5. **状态包节点**

```text
机械装调完成 [状态包 3/4]
```

### 9.2 活动节点形态

1. **虚拟活动节点**

```text
(V) 机械装调
状态：部分实现 2/3
子活动：5
最大深度：3
```

2. **可执行活动节点**

```text
(E) 安装左侧管路
前置状态：3
产出状态：2
继承前置：1
跨层级绑定：是
```

3. **虚拟活动容器展开**

```text
┌──────────────────── (V) 系统运行准备 ───────────────────┐
│                                                          │
│ (V) 上电准备                                             │
│ (E) 上电前检查                                           │
│ (E) 软件加载                                             │
│ (E) 通信检查                                             │
│                                                          │
│ 上下文：1  输出实现：3/4                                  │
└──────────────────────────────────────────────────────────┘
```

虚拟活动容器内部只显示活动节点。上下文前置状态、声明输出状态、原子活动输入状态和原子活动产出状态均显示在状态体系中，通过语义连线连接到虚拟活动或原子活动。

### 9.3 局部展开规则

系统默认折叠高层状态和虚拟活动，支持局部展开。

展开状态包时：

```text
状态包作为容器保留，内部显示成员状态引用实例。
```

状态包容器内部为局部自由画布，成员状态引用实例可自由拖动。外部边默认仍然连接到状态包边界，不自动拆成多条成员状态线。用户点击覆盖摘要或进入覆盖面板后，才查看具体覆盖成员。

不会自动展开成多条线，除非用户主动查看覆盖详情。

展开虚拟活动时：

```text
虚拟活动作为容器保留，内部只显示子虚拟活动和原子活动。
```

虚拟活动容器内部同样是局部自由画布，子活动可自由拖动。外部上下文前置和声明输出默认连接到虚拟活动容器边界；容器内原子活动与外部状态的真实 `input/output` 连线仅在选中节点、进入专注画布或切换到实现/求解视图时展开显示。

折叠虚拟活动时，内部活动和内部连线隐藏，节点只显示摘要：

```text
(V) 机械装调
子活动：6
输出实现：4/5
阻塞：1
```

### 9.4 语义端口与连线规则

节点连线必须通过固定端口发起，避免自由白板中出现语义不明的任意线。

状态节点端口：

- 左侧：被产出端口，接收活动输出。
- 右侧：前置端口，作为活动输入。
- 顶部：成员操作入口，仅用于添加状态、引用已有状态、展开/折叠，不发起业务连线。
- 底部：覆盖详情入口，不发起业务连线。

活动节点端口：

- 左侧：输入端口，接收状态前置。
- 右侧：输出端口，产出状态。
- 顶部：活动归属操作入口，仅用于添加子活动、移动所属虚拟活动、展开/折叠，不发起业务连线。
- 底部：进入专注画布或打开实现详情。

允许的业务连线：

| 起点 | 终点 | 角色 | 说明 | 推荐样式 |
| --- | --- | --- | --- | --- |
| 状态 | 虚拟活动 | `context_input` | 高层上下文前置，继承给内部可执行活动 | 蓝色实线，标签 `上下文` |
| 虚拟活动 | 状态 | `declared_output` | 虚拟活动声明目标状态或状态包 | 绿色实线，标签 `声明输出` |
| 状态 | 原子活动 | `input` | 原子活动真实求解前置 | 蓝色加粗线，标签 `输入` |
| 原子活动 | 状态 | `output` | 原子活动真实求解效果 | 绿色加粗线，标签 `输出` |

不允许的业务连线：

- 状态直接连状态表示业务依赖。
- 活动直接连活动表示执行依赖。
- 虚拟活动直接连原子活动表示求解依赖。
- 将状态包成员关系或活动归属画成主画布业务线。

如果用户需要表达活动先后关系，必须通过中间状态建模：

```text
状态A → 活动1 → 状态B → 活动2 → 状态C
```

### 9.5 复杂连线降噪规则

为避免自由画布在复杂场景中变乱，连线显示采用“默认摘要、聚焦展开”的规则：

- 默认只显示当前层级的主线，高层画布优先显示 `状态包 → 虚拟活动 → 状态包`。
- 状态包折叠时，状态包绑定显示为一条聚合线和 `覆盖 3/5` 摘要，不自动展开成 5 条成员状态线。
- 虚拟活动折叠时，内部活动和内部 `input/output` 隐藏，只显示 `上下文`、`输出`、`阻塞` 等摘要。
- 一个活动输入超过 5 个状态时，默认显示一条 `5 个输入` 汇总线，点击后展开具体扇入线。
- 一个活动输出超过 5 个状态时，默认显示一条 `5 个输出` 汇总线，点击后展开具体扇出线。
- 选中某个状态或活动时，只高亮它的上游、下游、继承前置和产出路径，其他线降透明度。
- 跨层级连接允许存在，但线上必须显示 `跨层级` 或 `状态包输入/输出` 标记，并在节点摘要中累计 `跨层级 N`。
- 线自动走通道并绕开节点，跨容器线优先从容器边界出入，不穿透容器内部节点。

### 9.6 活动创建向导规则

活动创建不要求用户先手工画两条边。推荐使用“选择状态 → 创建活动”的向导式交互。

状态选择规则：

- 前置状态和目标状态均支持单选或多选。
- 可从状态包列表、全局状态库选择，也可直接在画布选择。
- 可选择状态包，也可选择状态引用实例。
- 选择状态包时，系统按状态包处理，并生成覆盖快照。
- 选择状态引用实例时，系统按该真实状态处理。

活动信息编辑规则：

- 用户确认前置状态和目标状态后，再弹出活动信息编辑面板。
- 面板中需要明确当前创建的是虚拟活动还是原子活动。
- 虚拟活动需要维护：名称、编码、父虚拟活动、排序、说明、上下文前置、声明目标状态。
- 原子活动需要维护：名称、编码、所属虚拟活动、规则时长、排序、说明、前置状态、目标状态；新建时若已选择前置/目标状态，系统应同批生成两侧绑定草稿，且在目标状态可转换为 effect fact 时自动生成默认 `op_rule`，否则保存为待补规则状态。
- 保存后才在画布上生成活动节点和两端箭头。

错误处理：

- 如果原子活动没有规则，应允许先保存为“待补规则”状态，但求解器准备校验必须阻塞；如果用户在新建时选择了产出状态，系统应优先自动生成默认规则，只有产出状态无法转换为 effect fact 时才要求补充规则。
- 如果前置状态或目标状态为空，应禁止保存。
- 如果选择状态包作为目标状态，系统必须记录覆盖快照，并在状态包新增成员后提示 stale/partial。

### 9.7 虚拟活动专注画布规则

虚拟活动节点需要提供“进入专注画布”入口。

进入后：

- 面包屑显示当前路径，例如：`总画布 / 机械装调 / 结构装配`。
- 父虚拟活动的前置状态和目标状态自动出现在专注画布中，但作为容器外部边界状态显示。
- 用户可以继续创建虚拟活动或原子活动。
- 专注画布内的目标状态实现情况要回写到父虚拟活动节点摘要。
- 虚拟活动容器内部只允许放置活动节点，不能放置状态节点。
- 如需新增或引用状态，用户应通过全局状态库、状态包容器或状态区域操作，再用 `input/output` 与容器内原子活动连接。

退出后：

- 父画布中的虚拟活动节点显示内部实现摘要。
- 如果内部原子活动已经完整产出目标状态包，显示完成状态。
- 如果只实现部分目标状态，显示部分实现和缺失状态数量。

## 10. 跨层级绑定规则

系统允许活动跨层级绑定状态。

示例：

```text
(E) 功能点A验证

前置：
- 系统运行准备完成[高层状态包]
- 测试设备在线[低层状态]
- 测试脚本完成[低层状态]

产出：
- 功能点A通过[低层状态]
```

该行为不作为错误，但 UI 需要标记：

```text
该活动存在跨层级绑定
```

跨层级绑定显示规则：

- 原子活动连接高层状态包作为前置时，连线显示 `状态包输入`，节点显示 `跨层级 N`。
- 原子活动产出状态包时，保存前必须让用户选择覆盖范围：`全部当前成员`、`只选择部分成员` 或 `取消`。
- 保存覆盖范围后生成覆盖快照；状态包后续新增成员状态时，该绑定显示 `stale` 或 `partial`。
- 跨层级线默认从状态包或虚拟活动容器边界出入，只有选中相关节点、打开覆盖详情或进入专注画布时才展开真实端点。

## 11. 反向活动与返工建模

系统允许人为定义反向活动。

示例：

```text
[管路已安装]
        ↓
(E) 拆卸局部管路
        ↓
[管路已拆卸]
```

系统不自动推导状态失效关系。

拆卸、返工、复装都作为用户显式定义的活动和状态处理。

## 12. 校验规则

校验分为：

```text
建模校验
求解器准备校验
```

### 12.1 建模校验

建模阶段允许不完整，但需要提示问题。

检查项：

- 孤立状态
- 孤立活动
- 活动缺少前置状态
- 活动缺少产出状态
- 状态包为空或成员重复
- 活动容器循环
- 状态包覆盖缺口
- 被引用状态包修改未选择同步/分叉
- 虚拟活动未分解
- 虚拟活动部分实现
- 重复状态候选未处理
- 跨层级绑定提示
- 画布节点重叠
- 连线端点错位或路径穿过节点
- 专注画布边界状态缺失

### 12.2 求解器准备校验

以下问题应阻止进入求解：

- 可执行活动没有前置状态
- 可执行活动没有产出状态
- 存在循环依赖
- 存在不可达前置状态
- 存在未产出的必要状态
- 存在未解决的状态包覆盖缺口
- 虚拟活动声明输出但内部未实现
- 状态包成员覆盖不完整
- 活动参与求解标记错误

画布布局问题不阻止求解。只要底层状态、活动、绑定、覆盖快照和规则满足求解器准备要求，即使节点位置需要整理，求解器也可以通过既有数据库接口读取。

以下问题可作为警告：

- 产出状态没有下游使用
- 跨层级绑定较多
- 状态包覆盖范围过大
- 多个活动产出同一状态
- 同一状态被多个状态包复用

校验结果展示要求：

- 页面必须把建模校验、求解器准备校验和求解预检阻塞项展示为中文级别、中文问题类型、用户可读说明和建议操作，不应只展示后端原始 `code`、英文 `message` 或英文 `suggested_action`。
- 问题说明应尽量补充相关状态、活动或绑定对象；覆盖类问题应显示绑定编号和覆盖状态，虚拟活动实现问题应显示缺失叶子数量，规则类问题应显示相关规则 ID 或规则选择状态，健康检查问题应显示相关事实特征和值。
- 问题行必须提供 `定位` 操作；如果目标状态、活动或原子活动当前被局部范围或折叠深度隐藏，页面应自动调整焦点和展开深度后再选中对象。
- 带 `binding_id` 的覆盖问题应提供 `刷新` 操作；刷新覆盖属于写操作，只有进入编辑模式后才能加入编辑草稿，并且仍需通过 `统一提交` 才写入数据库。
- `统一提交` 的提交前复核也必须复用同一套中文问题说明。存在结构性建模 error 时应提示错误/警告数量，回滚本次提交并保留草稿；只有求解准备 error 或 warning 时，确认框应列出关键问题的中文摘要、对象和建议，并明确继续保存/返回编辑。
- `layered-expansion` / `layered-health-check` 返回的诊断应尽量映射回网络编辑器的真实状态、虚拟活动、原子活动或绑定对象；无法映射时也应显示来源类型和编号，便于排查数据问题。

## 15. 数据模型建议

### 15.1 State

```ts
type State = {
  id: string
  code: string
  name: string
  type: "NORMAL" | "MILESTONE" | "INTERFACE" | "CHECK"
  feature_key?: string
  operator?: "eq" | "gte" | "lte" | "gt" | "lt"
  target_value?: string
  description?: string
  created_at: string
  updated_at: string
}
```

### 15.2 StatePackage

```ts
type StatePackage = {
  id: string
  code: string
  name: string
  aggregation_rule: "AND"
  member_ids: string[]
  source_package_id?: string
  branch_reason?: string
  description?: string
  created_at: string
  updated_at: string
}
```

### 15.3 StatePackageMember

状态包成员表达“某个全局状态出现在某个状态包中”。它不是状态层级所有权关系。

```ts
type StatePackageMember = {
  id: string
  state_package_id: string
  state_id: string
  display_label?: string
  sort_order: number
  created_at: string
  updated_at: string
}
```

### 15.4 DuplicateStateCandidate

```ts
type DuplicateStateCandidate = {
  candidate_state_id: string
  match_reason:
    | "CODE_EXACT"
    | "NAME_EXACT"
    | "FACT_EXACT"
    | "NAME_SIMILAR"
  confidence: "HIGH" | "MEDIUM" | "LOW"
}
```

### 15.5 StatePackageChangeDecision

用于记录被引用状态包修改时用户选择同步还是分叉。

```ts
type StatePackageChangeDecision = {
  id: string
  source_package_id: string
  affected_package_ids: string[]
  decision: "SYNC_SHARED" | "BRANCH_CURRENT"

  changed_state_ids: string[]
  change_type: "ADD_MEMBER" | "REMOVE_MEMBER" | "REPLACE_MEMBERS"
  reason?: string
  created_at: string
}
```

### 15.6 Activity

```ts
type Activity = {
  id: string
  name: string
  level: number
  type: "VIRTUAL" | "EXECUTABLE"

  parent_activity_id?: string
  child_activity_ids: string[]

  input_bindings: StateBinding[]
  output_bindings: StateBinding[]

  context_input_bindings: StateBinding[]
  inherit_context: boolean

  solver_participation: boolean

  description?: string
  created_at: string
```

## 16. 求解器数据库接口对接规则

网络编辑器不生成独立导出文件、JSON 数据包或脱离数据库的中间模型。预览模式只读取已提交数据库数据；编辑模式中的变更先进入草稿，点击 `统一提交` 后再一次性写入现有数据库表或现有数据库接口承接的数据结构。求解器需要输入时，应通过既有数据库接口读取 canonical 数据。

接口对接原则：

1. 状态、状态包、状态包成员引用、活动、活动-状态绑定、覆盖快照和规则引用在编辑模式中先写入草稿。
2. `统一提交` 时，网络编辑器按一次事务或等效的批量提交语义调用现有主数据、规则、绑定、校验和求解相关接口。
3. 提交成功后，草稿内容成为数据库中的新 canonical 数据；提交失败时，不得产生半提交状态。
4. 网络编辑器不维护一套独立导出格式。
5. 求解器读取时只把可执行活动作为候选求解活动。
6. 虚拟活动不作为求解活动，只作为 group / WBS / display metadata 保留在数据库中。
7. 状态包绑定在求解读取阶段按覆盖快照展开为具体状态集合。
8. 虚拟活动的上下文前置在求解读取阶段继承给内部可执行活动。
9. 可执行活动自身前置、产出状态和 `op_rule` 仍以数据库中的规则与绑定为准。
10. 状态包 AND 聚合规则由状态包成员关系和 `aggregation_rule` 字段表达。
11. 求解前只需要执行“求解预检”，确认数据库中的 canonical 数据已满足求解器读取要求；只有预检 `ready` 且模板摘要标记为“数据库交接就绪”时，后续求解链路才可通过既有数据库接口读取这些数据。

示例：

数据库中维护：

```text
(V) 功能验证
上下文前置：
- 系统运行准备完成[状态包]

内部活动：
- (E) 功能点1验证
- (E) 功能点2验证
```

求解器通过既有接口读取后的等效语义：

```text
(E) 功能点1验证
前置：
- 系统运行准备完成[状态包展开结果]
- 功能点1自身前置状态

(E) 功能点2验证
前置：
- 系统运行准备完成[状态包展开结果]
- 功能点2自身前置状态
```

## 19. 关键设计结论

已确认的关键结论：

1. 编辑器服务于全流程集成场景。
2. 编辑器不仅可视化，还要能直接编辑模型。
3. 最终目标是服务求解器输入维护，并通过既有数据库接口对接求解链路。
4. 状态本体全局唯一，不携带层级所有权关系。
5. 状态包是命名状态集合，通过成员引用聚合状态。
6. 状态包通过全部成员状态 AND 聚合达成。
7. 活动必须遵循状态-活动-状态结构。
8. 活动依赖状态，不直接依赖活动。
9. 一个活动可以有多个前置状态和多个产出状态。
10. 一个状态可以由多个活动产出。
11. 活动采用节点形式，不作为普通边。
12. 交互层采用自由画布，语义层仍必须落到状态-活动-状态关系。
13. 边只表示状态与活动之间的输入/输出/上下文/声明输出关系，不允许无语义自由线。
14. 状态包绑定永远表示绑定该状态包的成员状态覆盖范围。
15. 新增状态包成员后，原有状态包绑定不自动覆盖新增成员。
16. 状态包绑定需要记录覆盖快照。
17. 默认折叠高层节点，支持任意层级展开/收起。
18. 展开状态包时，状态包作为容器保留，内部只包含状态引用实例。
19. 展开虚拟活动时，虚拟活动作为活动容器保留，内部只包含子虚拟活动和原子活动。
20. 支持状态和活动完全同步。
21. 支持全局自由布局、容器内部自由布局、局部坐标保存和自动整理。
22. 状态包成员关系和活动归属不通过业务连线表达。
23. 状态包成员引用通过引用实例、`引用` 角标、资源树、面包屑和属性面板表达。
24. 允许活动跨层级绑定状态，但必须显示 `跨层级` / `状态包输入` / `状态包输出` 等提示。
25. 用户通过选择前置状态和目标状态创建活动，系统生成活动节点和两端语义连接。
26. 高层活动可作为虚拟活动，用于自上而下建模。
27. 虚拟活动不参与求解器计算。
28. 虚拟活动可进入专注画布继续分解。
29. 专注画布中的边界状态仍属于状态体系，不进入虚拟活动容器。
30. 原子活动作为真正可执行活动参与求解器。
31. 虚拟活动需要通过内部可执行活动实现其声明输出。
32. 虚拟活动可提供上下文前置条件，并继承给内部可执行活动。
33. 同一状态可以在不同状态包下以引用实例形式出现。
34. 新建状态时必须自动识别重复状态，优先复用已有状态。
35. 修改已被引用的状态包成员时，系统必须让用户选择同步共享包或分叉当前状态包，不能静默传播或静默局部修改。
36. 同步会影响所有引用方并刷新覆盖状态；分叉会创建新状态包分支，当前上下文改用新分支，其他引用方保持不变。
37. 网络编辑器默认预览模式只读；进入编辑模式后所有变更进入草稿。
38. 只有点击统一提交后，草稿才一次性写入数据库；取消编辑会丢弃草稿。
39. 网络编辑器不导出独立数据文件，提交后的结果由既有数据库接口读取。
40. 需要建模校验和求解器准备校验两套校验机制。

## 20. 一句话产品定义

> 该编辑器是一个面向全流程集成的状态集合-活动分层网络建模工具，通过自由画布、专注画布、状态包成员引用、虚拟活动、局部展开、覆盖快照和求解器校验机制，支持用户从高层状态目标逐步下钻到可执行原子活动网络，并通过编辑草稿和统一提交把结构化、可校验、可维护的求解器输入维护到现有数据库中。
