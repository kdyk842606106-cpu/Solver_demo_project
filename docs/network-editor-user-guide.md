# 状态-活动网络编辑器用户与验收说明

> 适用版本：V0.3 网络编辑器 MVP
> 更新日期：2026-06-30
> 入口：前端 `数据管理 -> 网络编辑器`
> 验收矩阵：`docs/network-editor-acceptance-matrix.md`

## 1. 用途

状态-活动网络编辑器用于把分层状态、虚拟活动、原子活动、规则和求解器输入维护在同一个可视化工作区中。它不是独立的流程图系统，而是现有 V0.3 主数据模型的图形化入口：

- 状态仍以 `state_node` 为准。
- 一级/二级活动包仍以 `activity_node` 为准，并作为虚拟活动。
- 原子活动仍以 `atomic_activity + op_rule` 为准，并作为参与求解器执行的活动。
- 求解器仍读取 `op_rule.preconditions/effects`、分层展开和健康检查结果。

## 2. 建模工作流

本版本采用一次性提交操作流：页面打开后先是 `预览模式`；只有点击顶部 `进入编辑` 后，画板才允许拖动、连线、调整容器、新增状态或维护活动。编辑过程中的所有单步 `保存` 只进入左侧 `编辑草稿`，不会直接写数据库；编辑完整轮画板后，点击顶部 `统一提交` 才一次性校验并落库。没有处在有效编辑会话中时，页面一律按预览模式处理。

1. 在顶部选择设备类型。设备类型下拉会按 `最近使用`、`业务设备类型`、`测试 / 样例设备类型` 分组，仍可直接搜索编码或名称；切换后该设备类型会进入最近使用列表。
2. 页面默认进入 `预览模式`，只读取已提交数据库数据；此时可以查看、定位、展开/折叠、影响分析、校验和求解预检，但不能新建、删除、移动节点、调整容器、连线、刷新覆盖或维护状态包成员。重新打开页面、切换设备类型、刷新已提交数据、取消编辑和统一提交成功后也都会回到预览模式；只要没有再次点击 `进入编辑`，画板就保持只读。
3. 点击顶部 `进入编辑` 后进入 `编辑模式`，同时打开一个临时编辑草稿。只有处在这个编辑会话中，画板才允许修改；所有新增、编辑、删除、连线、覆盖刷新、布局调整、容器尺寸调整和状态包成员维护都会先进入左侧 `编辑草稿`，顶部显示未提交数量。单步保存、拖动或连线都不会直接写数据库；`统一提交` 是本次编辑会话唯一写库入口。提交成功后自动回到预览模式；结构性错误或用户在 `提交前复核` 中选择 `返回编辑` 时，草稿保留在编辑会话内。
4. 在中间 X6 单画布整理节点位置。
   - 默认 `状态转移` 视图采用状态优先知识图谱：画布以目标状态卡为主，每张状态卡显示达成活动、前置状态数量和关系提示；活动层级主要作为左侧资源树分类、过滤和右侧元数据来源，不再作为默认画布骨架。
   - 达成活动来自原子活动到目标状态的 `output` 绑定。通常一个目标状态对应一个达成活动、一个达成活动也只对应一个目标状态；缺少达成活动、多达成活动、达成活动产出多个状态、状态包直接作为目标等情况先显示为关系提示，不阻止继续建模。
   - 选中目标状态后，右侧会显示 `状态转移` 详情：目标状态、达成活动和前置状态。进入编辑模式后，可以从右侧选择已有原子活动作为达成活动，或创建新的达成活动；也可以为达成活动追加或移除前置状态。所有这些操作仍只进入 `编辑草稿`，必须点击 `统一提交` 才写库。
   - 状态包可作为前置状态绑定。选择状态包作为前置时，系统默认按该状态包当前启用原子状态生成覆盖快照，后续新增原子状态仍通过覆盖刷新或重新绑定显式处理。
   - 旧的状态/活动全量二部图仅作为开发和回归调试入口保留，可通过 `?networkEditorFullGraph=1` 或本地 `network-editor-full-graph=1` 打开；普通业务用户默认不需要进入该视图。
   - 中间区域只有一张大画布，状态、状态引用、状态包、虚拟活动、原子活动和语义线都在同一坐标系中；页面不再拆成左右两个图。
   - 画布引擎只负责节点、容器、端口、连线、缩放、平移、选择和拖拽；重复状态识别、同步 / 分叉、求解预检和统一提交仍由现有业务层完成。
   - 编辑模式下，节点左侧会显示布局拖动手柄；按住手柄拖动节点，松手后位置变化加入 `编辑草稿`。
   - 状态包节点和虚拟活动节点右上角会显示 `展开 / 折叠`。折叠时它们是普通高层节点；点击 `展开` 后，同一个业务对象切换为容器形态并显示内部成员；点击 `折叠` 后恢复为摘要节点。这个操作只是查看范围变化，预览模式也可使用，不会打开编辑会话，也不会写入草稿。
   - 编辑模式下，状态节点上会显示快捷操作：`编辑` 直接打开状态抽屉，状态包节点还会显示 `添加状态`，点击后把新状态作为该状态包的成员引用加入，并给出默认落点。
   - 右键状态或活动节点会打开节点菜单。状态菜单可设为状态焦点、编辑状态、给状态包添加状态成员；活动菜单可设为活动焦点，虚拟活动可进入专注画布，编辑模式下还可编辑活动或继续添加内部活动。
   - 需要从画布直接创建活动时，按住 `Ctrl` / `Shift` / `Cmd` 点击一个或多个状态节点，节点会以多选样式高亮，画布上方浮出 `已选 / 前置 / 产出` 工具条。点击 `设为前置` 后，所选状态会标成前置输入；再多选另一组状态并点击 `设为产出` 后，所选状态会标成目标输出。随后点击 `创建原子活动`，抽屉会自动带入这些前置/产出状态并生成原子活动绑定草稿；点击 `创建虚拟活动` 只创建管理包，不直接绑定已选状态。抽屉保存后仍然只加入 `编辑草稿`，必须等 `统一提交` 成功后才写入数据库。
   - 画布动作条会按当前选择给出下一步提示：未选中时提示先选状态和活动；只选状态时提示再选活动；只选活动时提示再选状态；同时选中状态和原子活动后，可在右侧编辑栏选择输入或产出角色并加入草稿。虚拟活动仅作为管理包，不能直接和状态绑定。拖拽端口时，提示会切换为当前释放目标说明。
   - 编辑模式下，在画布任意空白位置双击会打开新建状态抽屉；如果双击位置落在展开的状态包容器内部，新状态默认挂到该状态包下。状态包容器内部空白区域也可直接双击，新状态会落在该容器内的双击位置；双击容器标题或手柄不会触发新建。保存后新状态草稿会携带双击位置，统一提交成功后按该位置显示。
   - 状态包容器内部只放状态节点和状态引用实例；虚拟活动容器内部只放子虚拟活动和原子活动，不放状态。容器内部节点都允许自由调整位置。同一真实状态出现在多个状态包中时，每个引用实例可以单独摆放，拖动其中一个实例不会改变真实状态本体，也不会影响其他状态包里的同名实例位置。聚焦某个状态包时，连到该真实状态的语义线会优先落到当前状态包内的引用实例端点；底层绑定仍按真实状态本体保存。
   - 状态包容器和虚拟活动容器左上角会显示移动手柄；拖动后容器内节点整体跟随移动，各节点相对位置保持不变，并作为批量布局变更加入 `编辑草稿`。
   - 状态包容器和虚拟活动容器右下角会显示尺寸手柄；拖动后容器尺寸加入 `编辑草稿`。
   - 画布动作条右侧提供缩小、百分比重置和放大控件；缩放和平移只改变当前查看比例，不进入草稿、不写库。中间 X6 画布可通过拖拽或滚动查看更远位置；按住 `Ctrl` 或 `Alt` 滚轮也可快速缩放。
   - 点击顶部 `自动整理` 会按当前可见节点的层级和顺序重新排布状态、活动，整理结果同样先进入草稿。
   - 预览模式下只读取已提交位置和尺寸，不能拖动节点或调整容器；点击 `取消编辑` 会丢弃本次布局草稿并恢复已提交布局。
   - 点击 `统一提交` 成功后，布局位置和容器尺寸随节点 metadata 一起保存，重新打开网络编辑器仍按已提交布局显示。
5. 在左侧资源树维护状态树、活动包和原子活动。
   - 状态包和一级/二级活动旁的加号可以直接在状态包中添加状态、创建二级活动或原子活动；保存抽屉后只加入草稿，点击 `统一提交` 成功后资源树和画布才会刷新到已提交数据。
   - 新建状态保存前会自动识别重复状态；复用判断主要按同一设备类型下的状态名称，编码完全相同也视为明确复用信号。状态维度、二元目标值和分类只用于描述状态事实，不作为是否复用的身份依据。只有一个编码或名称强匹配候选时，系统会提示 `已发现相同状态，将复用`，并直接把已有状态作为引用加入当前状态包草稿；名称相似但不能唯一确定时，弹出 `发现相似状态`，可选择 `复用选中状态` 或 `仍然新建`。
   - 如果正在修改一个已被其他状态包复用的状态包，系统会弹出 `共享状态包修改确认`：上方 `影响预览` 会显示本次新增或移除的成员状态、受影响状态包、相关绑定数量和当前覆盖缺口。选择 `同步到共享状态包` 会影响所有使用方；选择 `分叉当前状态包` 会创建新状态包分支，当前使用方切到分支，其他使用方保持不变。新增成员时分支会复制原成员并加入新成员；移除成员时分支会复制原成员但跳过被移除成员。分叉必须填写分支名称和分支说明；后端统一提交也会拒绝缺少名称或说明的分叉请求。
   - 已有状态抽屉中的 `所在状态包` 只用于维护状态本体的默认归属。若这次改动会把状态加入或移出一个已被复用的状态包，系统会阻止直接保存，并提示改用左侧 `状态包成员` 表的 `添加` / `移除引用`，以便进入同步/分叉确认流。
   - 新建或编辑状态、虚拟活动、原子活动时，`编码` 可留空由后端自动生成；编辑已有节点时也可在抽屉中修改编码，统一提交时后端会继续执行同机型唯一性校验。虚拟活动和原子活动抽屉还可以维护 `说明`，原子活动新建时的说明会同步写入同批生成的默认规则说明。
   - 活动树会把二级活动包下的原子活动引用显示为 `原子` 条目；点击原子活动会定位到画布中的原子活动，并自动把活动展开深度提升到原子层。
   - `未布置节点` 会完整列出当前图视图中没有任何可见连接边的状态或活动，跟随左侧搜索框按编码/名称过滤，节点较多时在列表内滚动；点击条目可在画布中定位该节点。
   - 新建虚拟活动时只维护名称、编码、父级和说明等管理信息；虚拟活动不直接选择输入或产出状态，也不会自动生成状态绑定。需要表达状态转移时，请在虚拟活动内部创建或引用原子活动。
   - 新建原子活动时必须至少选择一个 `输入状态` 和一个 `产出状态`；保存后系统先创建原子活动草稿，再同批次创建 `input/output` 绑定草稿。产出状态能转换为规则 effect fact 时，系统同时创建默认 `op_rule` 草稿；产出状态暂时无法转换为 effect fact 时，原子活动会按“待补规则”加入草稿，统一提交后可保存到数据库，但求解准备校验会以 `EXECUTABLE_MISSING_RULE` 阻塞，直到补齐规则。选择状态包时，画布绑定仍保持用户选择的状态包，避免线条过多。
   - 新建原子活动的 `产出状态` 如果包含多个原子状态的状态包，抽屉内会出现覆盖范围选择。选择 `全部当前成员` 时，output 绑定和规则 effect 覆盖该状态包当前启用原子状态；选择 `选择部分成员` 时必须勾选原子状态，output 绑定和规则 effect 只覆盖所选原子状态；点击抽屉 `取消` 会放弃本次创建。
6. 在画布中连接状态和活动：
   - 编辑模式下节点显示左右语义端口；节点本体只负责选中，布局移动使用左侧布局手柄。
   - 从状态右侧 `输入` 端口拖到原子活动左侧输入端口，创建 `input`。
   - 从原子活动右侧 `产出` 端口拖到状态左侧 `产出` 接收端口，创建 `output`。
   - 从状态右侧 `输入` 端口拖到原子活动左侧输入端口，创建 `input`。
   - 从原子活动右侧 `产出` 端口拖到状态左侧 `产出` 接收端口，创建 `output`。
   - 当某个活动的输入或输出超过 5 条时，画布默认用一条 `N 个输入` 或 `N 个输出` 汇总线表示，避免自由白板被扇入/扇出线铺满；点击汇总线、选中相关活动或选中任一相关状态后，汇总线会展开成具体连线。高层容器折叠时，内部隐藏节点相关连线会先重定向到容器边界；展开容器后再显示内部具体端点。少量具体连线会在端口处上下错开，避免多条线完全重叠。
   - 松手后系统会把端点、角色、规则和覆盖范围预填到右侧 `创建绑定` 表单，并弹出确认；点击 `加入草稿` 才生成绑定草稿。若绑定的是包含多个原子状态的状态包，确认框主按钮为 `全部当前成员`，次按钮为 `选择部分成员`；选择部分成员后，在右侧 `覆盖` 控件勾选原子状态并点击 `连接`。原子活动只允许选择启用规则：没有启用规则时，页面提示先去活动能力或规则维护创建并启用 `op_rule`；存在多条启用规则时，系统不会自动猜测，会要求先在右侧选择一个规则后再点击 `连接`。
   - 右侧 `创建绑定` 表单在状态包绑定场景提供 `全部当前成员 / 选择部分成员` 覆盖范围；选择部分成员时必须至少勾选一个原子状态。选中已有绑定后也可用同一控件把覆盖范围改为全量或 partial，然后点击 `更新选中绑定` 加入草稿。
   - 选中一个原子活动后，也可以点击右侧 `批量绑定`，一次选择多个前置状态和多个产出状态；系统自动生成 `input/output` 草稿，并跳过已经存在或已在草稿中的重复绑定。批量绑定中的状态包默认覆盖全部当前启用原子状态；需要 partial 覆盖时用单条绑定表单处理。虚拟活动不提供批量状态绑定入口。
7. 选中绑定后，可在右侧修改角色、状态、活动或规则，点击 `更新选中绑定` 加入草稿；也可查看状态包覆盖快照。
   - 对原子活动绑定，网络编辑器会把 `input/output` 覆盖同步到对应 `op_rule.preconditions/effects`；只会清理绑定层实际新增或接管的事实，原本手写在 `op_rule` 上的同名事实会保留。
8. 向状态包新增成员状态后，运行校验或查看覆盖面板，确认是否出现 `stale` / `partial` 覆盖缺口。
9. 使用 `刷新覆盖` 明确把新增原子状态纳入该绑定的覆盖快照；该操作同样先加入草稿。
10. 选中状态或活动后，右侧 `影响分析` 会自动刷新；也可点击顶部 `影响分析` 手动重新拉取当前选择的影响路径。
11. 点击 `校验` 查看建模问题和求解器准备问题。
12. 点击 `求解预检` 查看原子活动、输入/输出事实和 `/solve/layered` 请求模板摘要；页面不下载独立 JSON 文件。预检为 `ready` 时，模板摘要显示“数据库交接就绪”；预检为 `blocked` 时，模板摘要显示“仅预检摘要：阻塞 N 项”，只用于排查，不可直接交给求解器。
13. 编辑完画板后点击 `统一提交`。这是网络编辑器唯一写库动作；后端会按草稿顺序在同一次请求中应用变更，并在提交前执行网络编辑器校验。若存在状态/活动层级环、引用环等结构性建模错误，本次提交回滚，草稿保留在编辑模式中。若只有求解准备阻塞项或非阻断提示，页面会先显示 `提交前复核` 确认框，列出最多 5 条中文问题摘要、对象和建议；用户点击 `继续提交` 后正式保存模型，但保存后的图仍可能显示 `暂不可求解`，必须修复求解准备问题后才能进入求解；点击 `返回编辑` 则留在编辑模式并保留草稿。提交成功后清空草稿、结束本次编辑会话并回到预览模式。进入编辑时系统会记录当前网络 revision；如果提交时发现数据库已被其他会话修改，本次提交会以冲突失败并保留草稿，用户可刷新已提交数据或取消编辑后重新进入编辑。
14. 点击 `取消编辑` 会弹出确认框；点击 `丢弃草稿` 后丢弃当前草稿并回到预览模式，点击 `返回编辑` 则保留草稿继续编辑。编辑模式下点击顶部 `刷新` 也会用同样的 `丢弃草稿 / 返回编辑` 确认方式重新读取已提交数据。取消或刷新成功后画板恢复只读，必须再次点击 `进入编辑` 才能继续修改。

## 3. 视图模式

| 模式 | 用途 | 典型显示 |
| --- | --- | --- |
| 纲要 | 自上而下建模 | 状态包、虚拟活动管理包、原子活动输入输出 |
| 状态转移 | 状态优先建模 | 目标状态卡、达成活动、前置状态和关系提示 |
| 求解 | 求解器准备检查 | 原子活动、展开后的状态事实、输入输出事实 |

`状态转移` 是原 `实现` 视图的用户侧表达，底层仍复用 `view_mode: "implementation"` 的后端图投影和统一提交协议；本次 MVP 不改变数据库结构、网络编辑器 API 枚举、求解器契约或持久化语义。

`求解` 视图默认只投影启用的 `op_rule`、启用活动端点和启用状态事实；画布顶部会提示该视图仅显示原子活动与求解事实投影，虚拟活动作为分组元数据保留在求解预检中。停用规则不会生成 legacy precondition/effect 边，也不会在求解预检中被自动选为 `op_rule_id`。绑定覆盖快照中如果仍保留已停用原子状态，默认求解预检的 inherited/own preconditions 与 effects 也会过滤这些停用状态事实。如需审计停用数据，可打开 `include_inactive` 查看停用规则和停用原子状态的投影痕迹，但默认求解交接仍按启用数据判断。

在纲要和实现视图中，一级/二级虚拟活动会以容器边框标出其可见子活动范围。容器只是图形化分组，不会成为求解器任务，也不直接绑定输入或产出状态；真正参与求解的是容器内部的原子活动及其绑定的 `op_rule`。容器摘要只用于查看子活动数量、层级深度和布局范围。

顶部总览会显示状态、活动、虚拟活动、原子活动、绑定、状态/活动深度、最长依赖链、覆盖缺口、跨层级绑定、孤立节点和阻塞项数量。

总览下方会显示求解就绪状态：`暂不可求解` 表示存在阻塞级求解器准备问题，`提交/求解前需复核` 表示仍有建模提示或非阻断求解器问题，`求解输入就绪` 表示当前图投影没有阻塞项。

状态包节点在画布上会显示 `覆盖 已覆盖/当前原子状态` 与绑定数量；如果任一状态包绑定为 `partial` 或 `stale`，节点会以警示样式显示，方便在进入右侧覆盖面板前先发现缺口。

状态包节点还会显示 `成员`、`深度` 和 `活动` 摘要，分别表示当前可见成员数量、成员展开深度跨度和相关状态-活动连接数量。

展开状态包时，高层状态包节点本身切换为容器形态，内部只显示状态节点和状态引用实例；折叠后恢复为摘要节点。容器不只是背景提示，而是该状态包在画布上的展开形态。

活动节点在画布上会显示 `子活动`、`深度`、`输入`、`输出` 和 `跨层级 N` 摘要，分别表示虚拟活动可见子活动数量、最大后代层级、原子活动输入、原子活动产出和跨层级绑定数量。历史 `context_input/declared_output` 数据只作为旧数据兼容展示，不作为新建模入口。

## 4. 深度控制

`状态深度` 和 `活动深度` 控制当前画布从选中根节点展开多少层：

- 默认 `状态深度 = 1`、`活动深度 = 2`，先以高层状态和一级/二级虚拟活动建模，避免首次进入时自动铺开完整网络。
- `0` 表示不限制，兼容旧行为。
- `状态深度 = 1` 只显示选中状态根。
- `活动深度 = 2` 显示一级/二级虚拟活动，不展开原子活动。
- `活动深度 = 3` 会把二级包下的原子活动显示出来。

局部查看时可先选中状态或活动，再使用：

- `聚焦选中`：把当前选中状态或活动设为焦点。
- `折叠选中`：把选中对象设为当前焦点，并折叠到 1 层。
- `展开一层`：在当前焦点下多展开一层。
- `展开全部`：保留当前焦点，但取消深度限制，展开完整子树。
- `清除焦点`：清除状态根和活动范围，回到默认全局视图。

虚拟活动节点上显示 `专注` 入口，预览模式下也可以点击查看；双击虚拟活动同样会进入该活动的专注画布。顶部会显示当前活动面包屑；专注画布中的 `上层` 会回到父虚拟活动，`退出` 会清空 activity scope；这些操作只改变查看上下文，不打开编辑会话，也不产生草稿。编辑模式下，一级虚拟活动节点显示 `子活动` 入口，二级虚拟活动节点显示 `原子` 入口，保存后仍然先进入 `编辑草稿`。

深度控制只影响网络编辑器投影，不改变数据库主数据，也不改变 Planner/Scheduler 的 canonical 求解链路。

## 5. 影响分析

选中状态或活动时，右侧 `影响分析` 面板会自动拉取当前选择的影响结果；顶部 `影响分析` 按钮可在调整焦点、深度或绑定后手动重新分析当前选择。

选中状态时，右侧 `影响分析` 面板显示：

- 上游产出活动。
- 下游依赖活动。
- 所在状态包路径。
- 其他出现位置。
- 状态包成员覆盖情况，包括原子状态数、状态包绑定数和原子状态标签。
- 被哪些状态包绑定使用。
- 影响的虚拟活动和原子活动。

同一状态可出现在多个状态包中，页面统一按“状态包成员引用”解释：该状态会参与所在状态包的局部展开、原子状态覆盖、绑定快照、`layered-expansion` 目标展开和 `layered-health-check` 诊断；右侧资源区状态包成员表使用 `移除引用`，只移除成员关系，不删除真实状态。若要删除状态本体，属性区按钮会显示 `删除状态本体`，确认框也会提示这不是移出状态包。

选中活动时，右侧 `影响分析` 面板显示：

- 直接前置状态。
- 历史继承前置状态兼容字段。
- 产出状态。
- 所属虚拟活动。
- 受影响状态包。
- 下游活动。
- 是否参与求解器。

活动影响分析会用标签列表展示直接前置、产出状态、所属虚拟活动、受影响状态包、下游活动和历史继承前置兼容字段，顶部数字只作为快速计数。

默认影响分析只按启用的 `activity_package_atomic_ref` 计算原子活动的所属虚拟活动；停用挂载不会继续出现在默认 `owner_virtual_activities` 中。需要复核历史挂载时，可使用 `include_inactive` 审计停用引用。

被影响分析识别的相关状态、活动和连接边会在画布中高亮，便于从列表快速对应到网络路径。

## 6. 校验语义

校验分为两层：

- 建模校验：模型可以保存，但建议修正。例如孤立节点、活动缺少输入或输出、未分解虚拟活动、部分覆盖。
- 求解器准备校验：会阻止求解预检进入 `ready` 和后续求解读取，但不阻止用户保存建模中的图。例如原子活动缺少输入/输出、没有启用 `op_rule`、只有停用 `op_rule`、存在多个启用 `op_rule` 但绑定未显式选择、状态-活动依赖环、覆盖快照过期。状态聚合环、状态成员引用环、活动容器环属于结构性建模错误，会阻止统一提交。非阻断提示包括同一状态出现在多个状态包、多个原子活动产出同一状态、跨层级绑定较多、状态包覆盖范围较大，以及产出状态没有下游活动且未被选为目标状态。

网络编辑器复用现有 `layered-expansion` 和 `layered-health-check` 能力，并额外检查覆盖快照、多状态包出现、孤立节点、重复状态名、跨层级绑定、结构环和多原子活动产出同一状态。

`BROKEN_CHAIN` / `NO_PROVIDER` 等 `layered-health-check` 问题会映射回网络编辑器中的真实状态或原子活动节点；点击问题行的 `定位` 可定位到对应节点。如果节点当前被局部范围或折叠深度隐藏，编辑器会自动调整焦点和展开深度后再选中它。带 `binding_id` 的覆盖问题也会先展开绑定两端，再选中绑定或执行覆盖刷新。`layered-expansion` 返回的目标停用、目标无原子状态、原子状态缺少 `feature_key`、活动包没有原子活动等诊断，也会尽量携带状态或活动对象，便于同一张问题表定位。

底部校验表格会显示中文级别、中文问题类型、用户可读说明和建议操作。说明会自动补充相关状态、活动或绑定对象，以及覆盖状态、缺失原子状态数量、规则 ID、事实特征等关键细节；建议用于提示进入编辑后刷新覆盖、补充绑定、创建规则、确认终点状态或调整目标范围。规则类问题行会额外显示 `规则` 动作，点击后先定位相关对象，再切换到 `活动能力` 页签创建、启用或明确选择规则。提交前 warning 复核框会复用同一套中文问题摘要。后端原始 `code/message/suggested_action` 仍作为接口协议保留；页面优先按 issue code 显示中文说明和建议，未知 code 也使用中文通用建议，不直接把英文诊断句子作为主要操作文案。

## 7. 代表性验收场景

### 7.1 准备数据

建立以下状态树：

```text
系统运行准备完成 [状态包]
  - 安全条件满足 [原子状态]

机械装调完成 [状态包]
  - 模块 A 已安装 [原子状态]
  - 模块 B 已安装 [原子状态]
```

建立以下活动：

```text
(V) 机械装调
  (V) 模块装配包
    (E) 安装模块 A
    (E) 安装模块 B
```

建立以下绑定：

- `安装检查 input <- 系统运行准备完成`
- `安装检查 output -> 机械装调完成`
- `安装模块 A input -> 安全条件满足`
- `安装模块 A output -> 模块 A 已安装`
- `安装模块 B input -> 安全条件满足`
- `安装模块 B output -> 模块 B 已安装`

### 7.2 覆盖快照验收

1. 对 `机械装调完成` 建立状态包输出绑定。
2. 新增第三个原子状态 `模块 C 已安装`。
3. 重新打开网络编辑器或点击校验。
4. 绑定覆盖应显示 `stale` 或 `partial`，缺失原子状态包含 `模块 C 已安装`。
5. 点击 `刷新覆盖` 后，覆盖状态恢复为 `complete`。

### 7.3 多状态包出现验收

1. 将 `模块 A 已安装` 作为成员引用加入另一个状态包。
2. 画布状态节点显示引用标记。
3. 选中该状态后，`影响分析` 面板显示所在状态包路径和其他出现位置。
4. 选中任一所在状态包作为局部状态根时，应能看到该状态及其原子状态；将该状态包作为绑定或求解目标时，覆盖快照和 goal facts 应包含对应成员原子状态。
5. 删除引用不应删除真实状态。

### 7.4 虚拟活动管理包验收

1. 从多选状态工具条点击 `创建虚拟活动`。
2. 保存虚拟活动草稿。
3. `编辑草稿` 中应只出现虚拟活动创建项，不自动追加状态绑定草稿。
4. 建模校验和求解器准备校验不应报告虚拟活动声明输出未实现。
5. 需要表达状态转移时，应在虚拟活动内部创建或引用原子活动，并把输入/产出状态绑定到原子活动。

### 7.5 求解预检验收

1. 选择目标状态根 `机械装调完成`。
2. 选择活动范围 `机械装调`。
3. 可切换到 `求解` 模式复核画布；求解预检会自动按求解视图和完整后代范围生成，不受当前画布折叠深度限制。
4. 点击 `求解预检`。
5. 预览中应只包含可执行原子活动，不把虚拟活动作为求解任务。
   - `ready` 时，`/solve/layered` 模板摘要只说明后续求解需要补齐的运行时字段，例如 `machine_id`、`current_state_id`。
   - `blocked` 时，模板摘要必须显示“仅预检摘要”，并展示阻塞项；页面不下载独立 JSON 或求解模板文件。
   - 只有停用 `op_rule` 的原子活动应保持阻塞状态，不应在默认求解预检中填入该停用 `op_rule_id`。
   - 覆盖快照中残留的停用原子状态不应进入默认求解预检的前置或效果事实；打开 `include_inactive` 时可用于审计。
6. 预览应展示：
   - `goal_facts`
   - `candidate_activities`
   - `effective_rules`
   - 状态聚合 `AND` 规则
   - 虚拟活动 group/WBS 元数据
   - 输入/产出事实
   - 自身输入/输出
   - `POST /api/v1/solve/layered` 请求模板
7. 若预览状态为 `blocked`，可查看阻塞项和摘要；`/solve/layered` 模板只作为预检摘要展示，不代表求解器可读取，页面也不下载独立 JSON 或求解模板文件。
8. 修复阻塞项并重新预览至 `ready` 后，求解器可通过现有数据库接口读取已提交 canonical 数据；若没有选择目标状态，模板会把 `target_state_node_ids` 标为待补齐字段；若没有选择活动范围，模板会自动填入有可执行后代的顶层活动范围，避免生成空候选活动的求解请求。

## 8. 当前不做

网络编辑器 MVP 不维护以下内容：

- 工期、成本和资源。
- 自动排程重做。
- OR / CUSTOM 聚合。
- 自动生成三级活动或原子活动。
- 自动状态回滚。
- 替代现有高级规则维护入口。

这些能力仍由现有规则、资源和求解页面承接，或作为后续扩展单独设计。
