# 状态—活动网络编辑器用户指南

> 适用版本：V0.3 / TICKET-097
> 更新日期：2026-07-28
> 当前唯一业务画布：`state_transition`

## 1. 这张图表达什么

网络编辑器把设备类型的能力模型表达为可供人员阅读、也可供求解器读取的状态转移知识图：

```text
输入状态 ──> 原子活动 ──> 输出状态
```

状态包和活动包负责组织与复用，不是新的状态事实或执行任务：

- 状态包通过 `StateNodeReference` 引用原子状态；
- 活动包通过 `ActivityPackageAtomicRef` 引用原子活动；
- 原子活动通过 `ActivityStateBinding(input/output)` 连接状态；
- 原子活动通过 `OpRule` 定义求解规则。

同一本体可出现在多个包中。画布上每个引用实例可拥有独立位置、排序和启用状态，但名称、编码、规则和状态绑定来自同一个本体。

## 2. 身份、改名与删除

名称和编码是可修改属性，不是身份。

- 修改原子状态或原子活动的名称、编码后，本体 ID、引用 ID、绑定 ID 和规则 ID 均不变；
- 两个引用实例会同步显示本体的新名称，但各自布局保持不变；
- 从包中移除成员只删除引用，不删除本体；
- 在用本体不能直接删除。系统返回 `BODY_IN_USE`，并列出引用、绑定、规则和历史计划使用数量；
- 只有没有任何引用、绑定、规则或历史计划使用时，才允许删除本体。

引用的两个端点创建后不可原地替换。需要把成员移到另一包或换成本体时，应删除旧引用并创建新引用。

## 3. 单一状态转移画布

页面不再提供纲要、实现、求解等业务视图切换，也不再提供活动包聚焦画布。

画布始终保持相同语义：

- 状态节点或状态引用实例；
- 原子活动的转移节点或活动引用实例；
- `input` 和 `output` 状态语义边；
- 状态包的展开、折叠和成员容器；
- 求解预检、健康检查和影响分析结果面板。

旧客户端仍可暂时提交 `outline`、`implementation` 或 `solver_ready`。后端会统一归一化为 `state_transition`，返回 `LEGACY_VIEW_MODE_NORMALIZED` 诊断，不再生成不同投影。

## 4. 推荐建模流程

1. 选择设备类型。
2. 创建或选择状态包。
3. 创建原子状态本体，填写状态维度、运算符和目标值。
4. 通过“引用状态”把原子状态加入一个或多个状态包。
5. 在“活动能力”页面创建或选择活动包。
6. 创建原子活动本体，并通过引用把它加入一个或多个活动包。
7. 为原子活动配置启用的 `OpRule`。
8. 在网络编辑器中为原子活动建立 `input/output` 状态绑定。
9. 执行结构校验与求解预检。
10. 检查草稿清单并统一提交。

活动包只提供分类、筛选和复用入口。要表达执行前提，必须建立“原子状态 → 原子活动”的 `input` 绑定；要表达执行结果，必须建立“原子活动 → 原子状态”的 `output` 绑定。

## 5. 引用实例和布局

画布区分 canonical 本体身份和 display 引用身份：

```text
state_node:51                     # 状态本体
state_node:51:ref:901             # 状态引用实例
atomic_activity:42                # 原子活动本体
atomic_activity:42:ref:700        # 活动引用实例
```

拖动一个引用实例只更新该引用的 `_network_editor_layout`，不会修改本体布局，也不会影响其他包中的引用实例。

绑定仍保存 canonical 本体端点。画布把同一绑定投影到当前可见引用实例时，会同时保留 `canonical_source_id` 和 `canonical_target_id`，因此展示位置不会改变求解身份。

## 6. 筛选、展开与资源树

顶部“状态根节点”和“活动范围”是筛选条件，不是视图切换：

- 状态筛选决定当前展开的状态包范围；
- 活动包筛选会先解析为明确的 canonical 原子活动 ID 集合；
- 清除筛选后恢复当前设备类型的完整状态转移语义；
- 状态包可展开一层或全部展开；
- 活动包保留在资源树和筛选器中，不作为可执行画布节点。

空活动范围表示使用当前设备类型下全部启用的原子活动。活动包引用是否启用、活动包所在层级或父级变化，不会隐式改变 canonical 有效模型。

## 7. 编辑草稿与统一提交

预览模式中的展开、筛选、校验和影响分析不会写数据库。

进入编辑模式后：

- 新建本体、引用、绑定和布局修改先进入草稿；
- 统一提交按同一事务校验和保存；
- 任一变更失败时整批回滚；
- revision 不一致时返回冲突，页面保留草稿供用户重新加载后处理；
- 修改绑定端点或输入/输出角色按“删除旧绑定 + 创建新绑定”处理，关系 ID 会变化。

Network Editor 不再创建或编辑活动包；活动包维护集中在“活动能力”页面。历史 `ActivityNode(level=3)` 只读兼容，不可新建。

## 8. 求解预检和有效模型

求解预检是同一画布上的动作与结果面板，不是第二张图。

预检和正式 layered solve 都调用统一有效模型解析器，以：

```text
目标状态 + canonical 原子活动范围 + 当前规则/绑定
```

生成同一份 `effective-model/v1`。解析结果包含：

- `effective_model_version`：规范化快照的 SHA-256；
- `effective_model_summary`：目标事实、候选活动、规则和阻塞数量；
- `effective_model_snapshot`：重放所需的目标事实、候选活动和有效规则。

每次求解把这三项写入 `SolveRequest.overrides`。以后即使当前本体改名、布局变化或规则升级，历史求解也可以读取当次保存的有效模型，而不是用当前数据库重新解释过去。

## 9. 影响分析

选择任一状态或活动引用实例执行影响分析时，系统先转换为 canonical 本体身份，再返回：

- 状态的引用包、消费者活动、提供者活动和下游状态；
- 活动的输入状态、输出状态、所属活动包和下游活动；
- 当前选择对应的 display 引用上下文。

同一本体的不同引用实例拥有相同业务影响，但所属包和显示位置不同。

## 10. 已日落能力

以下能力不再参与当前建模或求解：

- 活动包级 `context_input`、`declared_output` 绑定；
- `ActivityNode(level=3)` 新建与编辑；
- Scope Guard 新建、编辑、导入和包路径继承；
- 活动包专属画布、实现覆盖率及包级状态边；
- 多套业务图投影。

历史包级绑定和 Scope Guard 表只保留审计读取。它们不会生成图边、候选活动、有效前置条件或计划步骤，也不会自动转换为原子活动绑定。

若业务上确实存在公共准入条件，应显式为相关原子活动建立 `input` 状态绑定。

## 11. 验收操作

### 11.1 状态复用

1. 创建一个原子状态；
2. 引用到两个状态包并分别拖动；
3. 修改本体名称；
4. 移除其中一个引用。

预期：只有一个本体、两个引用；改名同步、布局独立；移除一个引用不影响另一个引用和本体。

### 11.2 活动复用

1. 创建一个带规则和输入/输出绑定的原子活动；
2. 引用到两个活动包；
3. 检查两个活动引用实例；
4. 执行求解预检和正式求解。

预期：只有一个 canonical 活动和一套规则；两个显示实例布局独立；求解只生成一个 canonical 任务。

### 11.3 安全删除

尝试删除仍有引用、绑定或规则的本体。

预期：返回结构化冲突，不删除任何依赖数据，并建议先移除引用或停用本体。

### 11.4 单画布

打开 Network Editor 并执行求解预检。

预期：没有业务视图切换器；预检面板出现但画布语义不变；页面不存在活动包聚焦或 Scope Guard 编辑入口。
