## 【第3页】为什么CP-SAT和LLM都不够用？

**状态**：✅ 内容已确定

**调整后内容**（双对比）：

### CP-SAT / 线性规划 / 关键路径法
- 擅长：给定工序列表后优化时间安排
- 死穴：状态不回退、无法推导工序、无法建模数值触发闭环
- 结论：优秀的"生产经理"（排时间），做不了"总工程师"（定工序）

### LLM（GPT-4 / Claude等）
- 擅长：理解自然语言描述、生成看似合理的计划
- 死穴：结果不可复现、可能幻觉、解释不可靠、数值计算易错
- 结论：优秀的"顾问"（启发思路），做不了"执行者"（生产环境）

### Solver差异化空间
```
CP-SAT(排时间) + Solver(定工序+排时间) + LLM(给建议)
```

**金句**：
> 这不是"又一个排程工具"，是"从0到1推导工序序列"的新品类。

## 【第4页】双层架构——为什么是结构性优势

**状态**：✅ 已确认

**内容**：
- 标题：双层架构——Planner 定工序，Scheduler 排时间
- 架构图：输入→Planner(状态空间推导)→Scheduler(CP-SAT资源排程)
- 管理层语言：Planner是"总工程师"定工序顺序，Scheduler是"生产经理"排时间表
- 结构性优势表格：逻辑正确性独立保障、资源优化可独立升级、可解释性在前置层

**金句**：
> 两者各司其职，接口稳定——Planner输出格式不变，Scheduler可随时替换更优算法。

## 【第5页】V0.3 当前能做到什么程度？

**状态**：✅ 已确认（经准确性审查）

**标题**：工程闭环已验证，核心场景可跑通

**已验证能力**（配Demo截图/录屏）：

| 能力 | 演示内容 | 状态 |
|------|---------|------|
| **常规排程** | 输入起点+目标，输出工序序列+甘特图（基础场景可用） | ✅ 基础能力可用 |
| **数值步进规划** | 水位0→80，步长20，自动生成4次注水步骤 | ✅ 可用 |
| **重复步骤实例化** | 同一规则执行多次，每次有独立ID | ✅ 可用 |
| **隐式子目标** | 前置条件不满足时，自动补齐中间步骤 | ✅ 可用 |
| **阻塞重排** | 某步骤卡住时，自动重规划或状态注入 | ✅ 可用 |

**具体案例**（配Demo截图/录屏）：
> **起点**：模块A已安装、电源下电、安装缺口=2  
> **目标**：所有模块已调测、电源上电、真空建立  
> **系统输出**：上电 → A调测 → 下电 → 建真空 → B调测 → 再上电 → ...
> 
> **关键特征**：上电/下电反复出现，由前置约束网络自然决定，非人工预设

**⚠️ 准确性声明**：
- V0.3 Phase 1 实现了"步进规划"（数值推进），但"事件驱动循环"（sub归零自动触发reset并插入清洁）尚未建模——此差距将在V0.5-V0.6补齐
- 常规排程在基础场景可用，但复杂长链路场景（多次状态回退）的求解质量依赖后续正向搜索架构升级

**核心价值**：
- ⚡ 秒级响应 | 📋 路径可解释 | 🔢 数值触发自动处理 | 🌿 主线自然涌现
