## 无法原样启用或必须调整的部分

1. **工作日历**：已实现项目统一日历及暂停续做。每次求解使用一个日历；暂不支持资源独立日历和不可中断活动。旧格式日历保留并明确阻止求解，不静默转换。具体字段、时间语义和部署要求见 `REACT_WORKBENCH.md`。
2. **五项调度原则**：已启用“精密易损吊装禁止夜班”，仅对有行吊需求且标记精密易损的活动生效，整项执行不能跨夜，普通活动可填补等待空档。行吊独占按行吊资源需求判定，调测独占按“功能调测”类型判定；各自开关开启后，对应作业执行期间禁止任何其他活动并行，等待开工不占场。按包连续、按责任组连续仍禁用。
3. **数值条件与增减运算**：原型关系编辑器允许 `neq/gt/gte/lt/lte/in`、`increment/decrement/sub` 等选项，当前后端语义是布尔原子状态。关系编辑展示“状态成立 / 消耗状态 / 产生状态 / 移除状态”，不能从名称解析数值或伪造运算效果。
4. **资源自由文本与具体实例**：原型允许直接填写责任组、空间名称及“工具 × 数量”字符串；真实系统必须选择已建立的资源 ID 并输入数量，避免同名或改名造成错误引用。为此保留多选和数量标签外观，使用结构化选择；人员、设备均是容量池，不分配具体实例。行吊/空间表补充容量列，启停和未分类资源也保留。
5. **吊装字段联动**：按最新标注提供“是否吊装”选择；选择“是”后显示行吊需求和精密易损，保存前必须选择行吊资源。选择“否”清除行吊需求并取消精密易损。重新打开时依据实际资源需求还原开关，避免保存两套矛盾数据。精密易损与风险标签仅为业务元数据。
6. **业务编码与状态标识**：按最新标注，活动编码由后端自动生成，页面不展示也不提供编辑。活动分类输入同样移除。旧业务编码和分类元数据保留，不在本次界面调整中删除历史数据。
7. **原型中的演示重置和硬编码项目**：未恢复清空演示数据的生产入口；顶栏改为重新加载当前数据库项目。项目切换、新建与版本都来自数据库，切换时仍可提交、放弃或取消。
8. **原型本地排程与固定默认结果**：未恢复浏览器递归选活动或串行排程函数。工期、并行、重复次数和时间全部取自真实联合求解结果；未选日历按连续自然分钟，选用日历按工作时段分段显示。保留预算、自动执行规模、校验状态、求解结论和历史等真实功能，因而结果区比原型多出视图页签和指标入口。

压缩包中的 `app/src/pages/Home.tsx` 是未被入口引用的 Vite 计数器样板，`components/ui` 是通用组件库，不是额外业务页面；没有把这些样板作为业务入口迁入。
