# Windows 一键部署

## 2026-11-09 更新（beta.4 快照）

默认使用最多 8 个 CP-SAT 搜索线程（受可用 CPU 数限制），独立 worker 仍一次处理一个求解任务。保留每 5 秒同步最好方案、同工期减少执行次数、工作日历、禁夜和作业独占等现有规则。多线程搜索具有不确定性，不保证所有案例都加速。

求解页新增初始状态诊断：提示缺失事实、无起点的依赖循环和不可用的活动来源，支持逐项确认并重新检查。提示是候选原因，不代表每项都必须补齐；只应确认现场确实成立的状态，结构可达也不代表满足所有资源和时间约束。

“设为项目初始状态”现在直接打开草稿提交预览，显示所选状态。点击“确认正式提交”后才保存；所有已有草稿将一起提交。继续编辑时保留“尚未保存”提示，版本冲突保留草稿。单项诊断确认只修改本次当前状态，不自动写入项目默认值。

本包仍内置 20 活动机械组装→功能调测案例，不包含源机器的测试A、数据库、运行历史或凭据。升级保留数据的方法见下方“升级与旧数据”，不要把新目录的独立数据库误认为旧数据丢失。

## 2026-11-05 更新（beta.3 快照）

本包包含 SVAR React Gantt 甘特图组件（MIT）、每 5 秒刷新最佳方案与搜索指标、同工期优先减少执行次数、按初始/目标状态动态裁剪重复实例，以及当次活动首次执行的日期时间窗。继续内置 20 活动机械组装→功能调测案例。甘特图支持刻度切换、滚动、日历暂停和重复执行，只读展示后端校验结果。`start-workbench.cmd` 已随包提供，不必另行下载。

### 升级与旧数据

将新包部署到一个全新目录会创建独立数据库，只包含内置示例；旧数据仍留在旧安装目录的 `.deployment` 中，不会自动迁移。

已有离线部署版需要保留项目和运行历史时：等待求解结束，运行旧目录的 `stop.bat`，完整备份旧安装目录（包括隐藏的 `.deployment`）；将新 ZIP 先解压到临时目录，再将包内文件复制覆盖到**原安装目录**。保留原 `.deployment` 和 `.venv`，不要删除、移动或用其他机器的文件替换它们，然后在原目录运行 `deploy.bat`。入口会读取原端口与配置，在迁移前备份原数据库并保留示例编辑。若出现错误，保留日志；恢复备份时也应恢复到原路径。此流程仅适用于本项目之前的 Windows 离线部署包；源码环境或其他数据库的迁移需另行备份恢复。

以下为通用安装说明。

发布包包含 React 构建产物、FastAPI、联合 CP-SAT、共享 Simulator/Validator、Python x64 运行时、锁定版本的离线 wheels、PostgreSQL 15 程序和数据库迁移。目标机器无需安装 Node.js、Python 或 PostgreSQL，不依赖源机器的 `D:\planner`。打包机需要已安装项目依赖的 Python、Node/npm、PostgreSQL 15 程序和可访问的 Python 包源；首次准备 wheels 需要联网。

在源码目录使用 `deploy/scripts/package_release.ps1` 打包；正式发布要求两个源码仓库均无未提交改动。`-AllowDirty` 仅用于验收当前未提交的工作区快照，包内记录主仓库/求解器提交号、dirty 标记、实际文件 SHA-256、Python 版本和真实迁移 head，不提交或清理任何源文件。前端在独立构建目录编译，不覆盖当前运行服务的 `frontend/dist`。

```powershell
deploy/scripts/package_release.ps1 -Version 0.3.1-beta.1 -PlannerRoot D:\planner -OutputDirectory D:\releases\planner-0.3.1
```

将 ZIP 解压到新的独立目录，双击 `deploy.bat`，或指定端口：

如果双击后窗口立即关闭，可在解压目录的地址栏输入 `powershell` 并回车，然后运行 `.\deploy.bat`，查看末尾的错误或成功地址。2026-11-05 版可从同一 GitHub Release 单独下载 `start-workbench.cmd`，放在与 `deploy.bat` 同级的目录后双击。这个诊断启动器会保留窗口并显示本次 `deploy-startup-*.log` 的完整路径；可直接用于原 ZIP，不需要覆盖其清单文件。自动化调用诊断启动器时可设置环境变量 `PLANNER_NO_PAUSE=1`。

```powershell
.\deploy.bat --api-port 8026 --db-port 55450
```

默认仅监听本机 127.0.0.1；前端与 API 同源，访问 `http://127.0.0.1:8026/`。这些端口已被占用时会明确退出，不会终止占用端口的进程，也不会连接它的数据库。初始化后端口和安装目录固定。不要复制源项目的 `.env`，本入口使用本目录生成的独立配置，并覆盖继承的数据库和求解器路径变量。

一键流程：校验发布文件 → 创建隔离虚拟环境 → 离线安装锁定依赖 → 初始化本目录 PostgreSQL 集群及应用数据库/账号 → Alembic 升级 → 启动隐藏的 API/worker → 检查 schema、内置求解器、前端 → 提交真实异步任务 → 校验日历/禁夜/两项独占和有效排程。只有全部通过才报告 ready；自检数据默认成功后删除，结果留在日志。`--keep-smoke-data` 可保留验收项目与运行历史。

首次成功部署会导入「20活动机械组装→功能调测｜集成验收到功能联调」，示例文件位于 `deploy/examples/assembly-commissioning-20.json`。打开项目的「联合求解」，当前状态选「集成验收待开展」，目标选「功能联调完成」，点击「求解」。默认连续自然分钟，参考结果为 20 次执行、515 分钟。页面每 5 秒更新一次，等工期时优先减少执行次数。小案例常在第一个刷新周期内完成，可直接看到最终方案。

重复运行 `deploy.bat` 会保留数据库与案例的编辑，不重复导入已安装的示例；先创建并校验 PostgreSQL 自定义格式备份，再检查迁移并重启本目录服务。有排队或运行中的求解任务时拒绝重启。运行 `stop.bat` 仅停止本安装目录的 API、worker、数据库；通过进程路径、启动时间及数据库数据目录检查归属，数据库文件不删除。该入口使用后台进程，暂不注册 Windows 服务或开机自动启动；机器重启后重新运行 `deploy.bat`。

数据、随机生成的数据库凭据及部署结果保存在 `.deployment`，日志在 `.deployment/logs`，备份在 `.deployment/backups`，最后一次验收在 `.deployment/verification.json`。不要将 `.deployment/config.json` 或数据库目录对外共享。包中不包含原有 `.env`、数据库、业务项目或运行历史；迁移旧业务数据应先备份并按独立迁移方案恢复，不能将本入口直接指向正在使用的业务库。

故障时保留日志与数据，不自动清空或回滚数据库。修复原因后在同一目录重试。发布包附带 `MANIFEST.json` 和 ZIP SHA-256；部署会校验包内所有清单文件。初始化后的目录不应移动，因为虚拟环境及 PostgreSQL 状态含有路径引用。
