## 数据与界面行为

- 一个项目对应一个 Planner 共享场景，项目列表和 revision 从数据库读取。所有活动、包和资源修改统一进入草稿，通过 `draft-commit` 原子提交。刷新前提示未提交修改；草稿只在当前页面会话中保留。项目切换可提交、放弃或取消；版本冲突不会覆盖服务端数据。
- 活动包仍为两级层级。活动可被多个二级包引用，移出仅删引用；删除父包会在同一草稿事务中先删子包。实现状态由活动自动绑定，改名不改 ID。前置保留、转移消耗和独立破坏不互相推断。
- 人员、行吊池、空间和可重复使用工具使用结构化容量资源。旧资源无分类时显示“未分类”。修改/删除资源支持 API 和草稿操作；存在活动引用时禁止删除或停用，容量不能低于任何单活动需求。
- 活动 `metadata` 保存类别、类型、说明、风险作业和精密易损信息，仅作业务描述。资源 ID 和数量只保存在 `resource_reqs`。JSON/Excel 导入导出保留元数据和资源分类，Excel 的新列可缺省；JSON 导入会重映射资源引用。
- 新建 API 场景默认并行、60 秒预算。共享 `new_scenario()` 的历史默认行为不变。首期仅优化总工期，默认随机种子 11；React 中总步骤上限和新活动的单项次数上限均自动设置，无需用户填写。
- 项目统一工作日历已启用。精密易损吊装禁夜规则已启用；行吊独占、调测独占、活动包连续、责任组连续仍禁用；旧格式日历、调度规则、计划调整、资源实例及改变状态的外部事件仍明确拒绝。
- 未选日历时开始日期仅作为展示基准；选择日历时同时确定实际工作时段，时区随请求保存。历史排程的名称与资源来自当次快照；重复执行按活动 ID 和 ordinal 区分。

## 运行契约

同步 `POST /api/v1/planner-runs` 保持兼容。新接口 `POST /api/v1/planner-runs/async` 固定 `engine=JOINT_CP_SAT`，接收原有场景/版本、当前状态、目标状态、预算，以及：

- `client_request_id`：最长 64 字符，唯一幂等标识。同标识同请求返回同一运行；同标识不同内容返回 409。前端在网络重试时复用标识。
- `display_start_at`：带时区偏移的日期时间，仅用于显示。
- `display_timezone`：IANA 时区，默认 `Asia/Shanghai`。

接口先完成版本、引用和能力校验，再提交不可变输入快照与队列记录，持久化成功后返回 202。现有列表和详情 GET 接口增加 `run_id`、`job_status`、`started_at`、`error_message`；`status` 保留求解结论，历史同步运行的 `job_status` 为空。

队列生命周期为 `QUEUED → RUNNING → FINISHED/FAILED`。`FINISHED` 表示求解调用完成，不能据此判断有解。结果仍区分最优、可行、超时有解、超时无解、已证明无解、未知、不支持及错误。

worker 使用 PostgreSQL advisory transaction lock 和行锁领取任务，短事务不覆盖求解过程。租约 45 秒，运行期间约每 2 秒续租；过期任务由 worker 标记 `FAILED/WORKER_INTERRUPTED`，不会自动重算。执行 token 和未过期租约共同保护续租及最终回写。子进程超过预算额外 120 秒仍未返回时触发 watchdog，标记执行失败，不冒充“无解”。

页面进入求解时立即查询，此后每 5 秒读取 `GET /api/v1/planner-runs/{run_id}/progress?known_plan_version=N`。首个经回放校验的方案立即保存，随后的指标和方案改善按 5 秒合并，终态立即提交。方案版本相同时响应只含指标。搜索分支与冲突取自 CP-SAT 的候选回调及阶段结束采样，两阶段累计，速度按同阶段相邻采样计算。最近采样时间与最近改善时间分开展示。断网恢复后查询最新版本，任务结束后停止轮询；执行中断仍可查看已保存的候选。
