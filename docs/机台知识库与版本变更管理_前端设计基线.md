## 2. 前端设计原则

1. **按现有业务工作流划分界面**：先配置、再建模、再管理正式版本。
2. **不按实体类型无限拆页**：状态、活动、资源、日历是工作步骤中的内容，不各占一个二级页面。
3. **业务范围只选择一次**：机台类型或机台实例由共享范围栏统一控制。
4. **草稿跨配置和建模保留**：用户可以连续完成一批有依赖的修改，再统一验证、提交。
5. **编辑与版本治理分离**：编辑状态只处理未提交草稿；版本管理只处理已经提交的不可变版本。
6. **历史内容默认只读**：任何“恢复”都先形成新草稿，再提交为新版本。
7. **运行时输入不伪装成知识**：当前状态、目标状态、临时资源可用性和求解开始时间放在求解页。
8. **界面使用业务语言**：普通界面不暴露 Git、Manifest、对象哈希等实现词汇。

## 3. 信息架构

### 3.1 顶部主导航

顶部主导航保持两个业务入口：

```text
机台知识库 | 求解
```

“求解”继续作为独立主页面，不嵌入 Network Editor。

### 3.2 机台知识库二级导航

机台知识库固定为三个二级页面：

```text
基础配置
→ 模型构建
→ 版本管理
```

三个页面共享相同的业务范围、当前版本、草稿和健康状态。

### 3.3 页面关系

```text
┌──────────────┐
│   基础配置   │  机台、状态维度、资源、日历
└──────┬───────┘
       │ 共享草稿
       ▼
┌──────────────┐
│   模型构建   │  状态 → 活动 → 转移关系 → 检查提交
└──────┬───────┘
       │ 生成正式版本
       ▼
┌──────────────┐
│   版本管理   │  历史、比较、回写、升级、引用
└──────┬───────┘
       │ 选择实例正式版本
       ▼
┌──────────────┐
│     求解     │  运行时输入、求解、重放
└──────────────┘
```

## 4. 共享范围栏

### 4.1 固定位置

范围栏固定在机台知识库三个二级页面顶部：

```text
[机台类型基线 / 机台实例 ▾]
[机台类型 ▾]
[机台实例 ▾]
当前版本 │ 冻结基线 │ 主线最新 │ 健康状态 │ 草稿数量
```

### 4.2 基线模式

显示：

- 机台类型选择器；
- 当前基线版本，例如 `B-000024`；
- 当前版本状态：可求解或暂不可求解；
- 草稿数量；
- “进入编辑”“查看变化”“提交版本”快捷动作。

隐藏：

- 机台实例选择器；
- 冻结基线；
- 升级提示。

### 4.3 实例模式

显示：

- 机台类型，只读显示实例所属类型；
- 机台实例选择器；
- 当前实例版本，例如 `I-000008`；
- 冻结基线，例如 `B-000021`；
- 基线主线最新版本，例如 `B-000024`；
- 是否存在可用升级；
- 当前版本状态和草稿数量；
- “回写变化”“升级基线”等条件动作。

### 4.4 切换保护

| 当前情况 | 切换行为 |
|---|---|
| 无草稿 | 直接切换并加载目标范围 |
| 有草稿 | 阻止切换，要求“返回编辑”或“放弃草稿” |
| 正在验证或提交 | 禁止切换 |
| 历史版本只读 | 允许关闭历史视图后切换 |
| API 加载失败 | 保留原范围，不显示半加载目标 |

MVP 不提供服务端长期草稿。草稿保存在当前浏览器会话，并按“范围 + 基础版本”隔离。

### 4.5 可分享地址

URL 至少保存：

```text
/knowledge
  ?stage=configuration|model|versions
  &scope=baseline|instance
  &machine_type_id=...
  &machine_id=...
  &revision_id=...
```

`revision_id` 存在且不是当前头版本时，页面进入历史只读模式。

## 5. 基础配置页面

### 5.1 页面目标

按依赖顺序完成机台建档和知识模型所需的基础配置：

```text
① 机台信息
→ ② 状态维度
→ ③ 资源配置
→ ④ 工作日历
```

四个区块使用步骤栏或纵向锚点，不作为新的二级页面。

### 5.2 机台信息

#### 基线模式

维护：

- 机台类型名称、编码和说明；
- 启用状态；
- 作为业务模板仍成立的其他基本属性。

#### 实例模式

维护：

- 具体机台名称、编码、位置；
- 所属机台类型，只读；
- 当前冻结基线，只读并提供“前往版本管理”；
- 仅属于具体集成设备的参数。

### 5.3 状态维度

维护状态维度及值域。实例模式默认显示基线继承内容，并允许实例新增或覆盖状态维度；这些变化必须进入实例草稿和版本，不得反向修改基线或全局定义。

界面必须动态读取状态维度，禁止在前端硬编码 `feature_key`。

### 5.4 资源配置

#### 基线模式

- 资源类型；
- 能力模型可引用的资源分类；
- 与机台类型有关的默认排程配置。

#### 实例模式

- 具体机器资源；
- 资源容量和启用状态；
- 与基线资源需求的匹配情况；
- 实例排程配置。

### 5.5 工作日历

#### 基线模式

- 工作日历模板引用；
- 状态维度到日历模板的配置；
- 默认日历策略。

#### 实例模式

- 实例默认工作日历；
- 状态维度日历映射；
- 当前引用的日历修订。

工作日历仍可保留自身的不可变修订，但改变机台使用的日历修订必须进入知识草稿，并通过新的知识版本生效。

### 5.6 新建机台类型

```text
点击“新建机台类型”
→ 填写机台信息
→ 进入初始化草稿
→ 配置状态维度、资源和日历
→ 前往模型构建
→ 检查并创建 B-000001
```

首个版本创建前，范围栏显示“尚未建立基线”，不能进入求解。

### 5.7 新建机台实例

```text
点击“新建机台实例”
→ 填写实例信息
→ 选择机台类型
→ 选择冻结基线，默认最新可求解基线
→ 配置实例资源和工作日历
→ 预览完整实例模型
→ 检查并创建 I-000001
```

选择暂不可求解基线时必须显示强警告；MVP 默认禁止从结构无效的基线创建实例。

### 5.8 Excel 导入

导入不得直接写当前正式版本：

```text
选择 Excel
→ dry-run
→ 显示新增、修改、删除和错误
→ 选择导入目标范围
→ 生成共享草稿
→ 前往“检查提交”
→ 创建新版本
```

导入失败时不改变当前版本；已生成的本地草稿必须保留或允许用户明确放弃。

### 5.9 不在本页面维护的内容

- 当前状态快照；
- 目标状态快照；
- 临时资源可用性；
- 求解开始时间；
- 求解结果和候选计划。

这些内容归入求解页的运行时输入。

## 6. 模型构建页面

### 6.1 固定步骤

```text
① 状态建模
→ ② 活动建模
→ ③ 转移关系
→ ④ 检查提交
```

步骤切换只改变工作区，不提交数据。四个步骤共享同一草稿和基础版本。

### 6.2 状态建模

维护：

- 状态包；
- 原子状态本体；
- 状态包成员引用；
- 原子状态的状态维度、运算符和目标值；
- 引用别名、排序、启用和布局。

交互规则：

- 原子状态是可复用本体；
- 加入多个状态包只新增多个引用；
- 删除引用不删除本体；
- 删除仍被引用的本体必须显示结构化冲突；
- 改名不改变身份和关系；
- 同一状态本体的不同画布引用可以拥有不同布局。

### 6.3 活动建模

维护：

- 一级、二级活动包；
- 原子活动本体；
- 活动包原子活动引用；
- 原子活动规则；
- 前置、效果、时长和资源需求；
- 责任子系统等能力属性。

交互规则：

- 活动包只管理和引用原子活动；
- 活动包不拥有原子活动；
- 删除活动包或引用不删除原子活动；
- 原子活动可被多个活动包复用；
- 活动包层级、名称和成员变化不应隐式改变有效求解模型；
- 不允许新建虚拟活动或旧三级执行活动。

### 6.4 转移关系

复用现有 Network Editor，并固定为唯一完整状态转移画布：

```text
原子状态 ── input ──> 原子活动 ── output ──> 原子状态
                          │
                          ├── 工序规则
                          └── 资源需求
```

#### 页面布局

- 左侧：状态包、状态引用、活动包和原子活动资源树；
- 中间：完整状态转移图；
- 右侧：选中本体、引用或关系的属性；
- 底部：影响分析、结构问题和求解准备摘要。

#### 明确日落

- 纲要视图；
- 求解视图；
- 视图切换器；
- 虚拟活动聚焦画布；
- 活动包级状态绑定；
- Scope Guard；
- 维护意图。

#### 关系交互

关系端点或角色不可原地替换。界面表现为一次用户动作，草稿中表达为：

```text
删除旧关系 + 创建新关系
```

对象改名只产生字段修改，不产生“删除对象 + 新增对象”。

#### 大图限制

- 对象树使用虚拟滚动；
- 画布按状态根、活动范围和展开深度加载；
- 默认首屏不超过 500 个图元素；
- 预计超过 1,000 个图元素时要求用户缩小范围；
- 筛选只改变显示范围，不改变正式知识或求解身份。

### 6.5 检查提交

检查提交汇总基础配置和模型构建的全部草稿。

#### 变化摘要

- 对象新增、修改、删除；
- 关系新增、修改、删除；
- 资源和日历变化；
- 纯布局变化；
- 系统补充或规范化的变化。

#### 验证层级

1. 结构完整性；
2. 模型健康；
3. 求解准备。

#### 提交弹窗

显示：

- 基础版本；
- 提交说明，必填；
- 变化统计；
- 结构错误；
- 求解阻断；
- 非阻断提醒；
- “保存为暂不可求解版本”确认项。

规则：

- 结构错误禁止提交；
- 没有变化时禁用提交；
- 求解阻断允许保存，但必须明确确认；
- 成功后生成新正式版本并清空当前草稿；
- 失败、超时或并发冲突不清空草稿。

## 7. 版本管理页面

### 7.1 职责边界

版本管理只处理已提交版本：

- 查看历史；
- 比较版本；
- 查看引用；
- 发起回写或升级；
- 从历史内容创建新草稿。

版本管理不得提供任意状态、活动、规则、资源或日历编辑表单。

### 7.2 页面布局

```text
┌─────────────┬──────────────────────┬──────────────────────┐
│ 版本时间线  │ 变化列表             │ 字段/关系/依赖详情   │
│ B-000024    │ 新增 / 修改 / 删除   │ Base / 当前 / 目标   │
│ B-000023    │ 对象 / 关系 / 布局   │ 影响与引用           │
└─────────────┴──────────────────────┴──────────────────────┘
```

版本时间线分页加载，默认每页 50 条。

### 7.3 版本详情

显示：

- 业务版本号；
- 提交说明；
- 父版本；
- 创建时间；
- 可求解状态；
- 变化数量；
- 对于实例：冻结基线；
- 引用该版本的实例和求解记录。

内容哈希和 UUID 收纳在“技术详情”，不作为主界面信息。

### 7.4 版本比较

支持比较同一业务范围内任意两个版本，以及实例头版本与其冻结基线。

差异分类：

- 对象新增、修改、删除；
- 关系新增、修改、删除；
- 布局变化。

图形差异使用：

- 绿色：新增；
- 黄色：修改；
- 红色：删除；
- 灰色：未变化。

关系端点变化必须明确展示为旧关系删除和新关系新增。

### 7.5 历史版本查看与恢复

历史版本只能只读打开，顶部持续显示“历史版本，只读”。

“以此版本恢复”执行：

```text
选择历史版本
→ 以历史 Manifest 创建新草稿
→ 跳转模型构建的检查提交
→ 验证
→ 提交为新的头版本
```

不得直接将版本指针移动到历史版本。

### 7.6 部分回写交互

实例模式提供“回写变化”：

1. 比较冻结基线与实例当前版本；
2. 用户选择对象、关系或顶层字段；
3. 布局变化默认不选；
4. 展示系统补齐的依赖，必要依赖不可取消；
5. 与基线主线执行三方合并；
6. 逐项处理冲突；
7. 查看结构和求解准备结果；
8. 填写回写原因；
9. 确认生成新基线版本。

完成后必须明确提示：

- 基线已生成新版本；
- 原实例未改变；
- 原实例仍冻结在原基线；
- 如需采用新基线，应继续执行实例升级。

### 7.7 实例升级交互

实例模式在主线高于冻结基线时显示“有可用升级”。

升级步骤：

1. 选择目标基线，默认主线最新；
2. 查看基线变化和实例本地变化；
3. 预览自动合并结果；
4. 解决冲突；
5. 验证升级后的完整实例模型；
6. 确认创建新实例版本并更新冻结基线。

任一步失败时，当前实例版本和冻结基线保持不变。

## 8. 统一编辑状态机

### 8.1 正常路径

```text
preview
→ editing
→ validating
→ submitting
→ preview
```

| 状态 | 可做 | 不可做 |
|---|---|---|
| `preview` | 浏览、筛选、比较、进入编辑 | 修改正式内容 |
| `editing` | 修改、撤销、跨前两个阶段切换 | 切换业务范围 |
| `validating` | 查看校验进度 | 继续修改、提交 |
| `submitting` | 等待结果 | 重复提交、切换范围 |
| `conflict` | 比较新头版本、重新应用、放弃 | 强制覆盖 |
| `historical_readonly` | 浏览、比较、创建恢复草稿 | 原地编辑历史 |

### 8.2 并发冲突

```text
submitting
→ conflict
→ 保留草稿
→ 加载当前最新头版本
→ 比较并重新应用草稿
→ validating
→ submitting
```

前端不得提供“忽略版本并覆盖”按钮。

### 8.3 草稿恢复

- 使用浏览器会话存储；
- 键由范围和基础版本组成；
- 只恢复到相同基础版本；
- 若头版本已移动，进入冲突流程；
- 成功提交或明确放弃后清理；
- 草稿不是正式版本，不得被求解读取。

## 9. 端到端工作流

### 9.1 创建首个机台类型基线

```text
基础配置
→ 创建机台类型
→ 配置状态维度、资源和日历
→ 模型构建
→ 状态建模
→ 活动建模
→ 转移关系
→ 检查提交
→ 生成 B-000001
→ 版本管理查看结果
```

### 9.2 创建机台实例

```text
基础配置
→ 新建机台实例
→ 选择冻结基线
→ 配置实例资源和日历
→ 模型构建查看继承内容
→ 按需增加实例变化
→ 检查提交
→ 生成 I-000001
```

### 9.3 日常修改基线或实例

```text
选择业务范围
→ 进入编辑
→ 在基础配置和模型构建间完成修改
→ 检查提交
→ 生成新版本
→ 版本管理查看差异
```

### 9.4 历史求解重放

```text
求解记录
→ 查看当次知识版本和运行时快照
→ 只读打开历史知识
→ 检查重放条件
→ 使用原知识版本和快照重跑
→ 比较结果
```

当必要运行时输入不完整时，仍允许查看历史输入，但禁用重跑并解释原因。

## 10. 页面状态与反馈

| 状态 | 页面反馈 | 可用动作 |
|---|---|---|
| 加载中 | 骨架屏，保留范围栏 | 等待、取消返回 |
| 无机台类型 | 引导创建首个类型 | 新建、导入 |
| 无机台实例 | 说明需先有可用基线 | 新建实例 |
| 尚无首个版本 | 显示初始化草稿 | 继续配置、检查提交 |
| 无草稿变化 | 草稿数为 0 | 浏览、进入编辑 |
| 结构错误 | 红色阻断并可定位 | 返回修复 |
| 暂不可求解 | 黄色状态，禁用求解 | 查看问题、继续编辑 |
| 有可用升级 | 显示冻结/最新版本差异 | 发起升级 |
| 主线并发变化 | 保留草稿并显示新头版本 | 比较并重新应用 |
| 历史版本 | 持续只读横幅 | 比较、创建恢复草稿 |
| API 失败 | 中文错误，不清空草稿 | 重试、返回编辑 |

错误信息通过统一错误码映射显示，不直接透出后端堆栈或英文异常。

## 11. 前端组件边界

### 11.1 共享组件

- `KnowledgeScopeBar`：业务范围、版本和草稿状态；
- `KnowledgeDraftSummary`：共享草稿摘要；
- `KnowledgeValidationPanel`：结构、健康和求解准备问题；
- `RevisionStatusBadge`：可求解/阻断/历史只读状态。

### 11.2 基础配置

复用现有机台类型、机台实例、状态维度、资源和工作日历能力，统一接入共享范围和草稿，不保留原独立二级入口。

### 11.3 模型构建

复用：

- 状态目标工作台；
- 活动能力工作台；
- Network Editor；
- 验证工作区。

Network Editor 只接受 `state_transition`，不再拥有业务范围选择器和多视图切换器。

### 11.4 版本管理

新增：

- `RevisionTimeline`；
- `RevisionDiffWorkspace`；
- `WritebackWizard`；
- `UpgradeWizard`；
- `HistoricalRevisionViewer`。

### 11.5 求解

状态快照和临时条件移入求解输入；求解页面只读取正式实例版本，不读取浏览器草稿。

所有 API 调用必须通过 `frontend/src/api/` 封装，组件不得直接调用 Axios。

## 12. 前端操作与后端能力映射

| 前端操作 | 后端能力 |
|---|---|
| 进入基础配置或模型构建 | 加载范围当前头版本及模型 |
| 保存草稿 | 浏览器会话草稿，不移动版本指针 |
| 检查提交 | `validate` + `commit` |
| 查看历史 | revision history |
| 比较版本 | diff |
| 只读打开历史模型 | load immutable revision |
| 从历史恢复 | load revision + create local draft + commit |
| 部分回写 | dependency closure + three-way merge |
| 实例升级 | upgrade three-way merge |
| 发起求解 | resolve `effective-model/v2` from instance revision |
| 历史求解 | revision load + replay snapshot |

具体路径、请求响应和错误码以[后端设计基线](./机台知识库与版本变更管理_后端设计基线.md)为准。

## 13. 性能基线

- 大型对象树和差异列表使用虚拟滚动；
- 版本历史默认每页 50 条；
- 图首屏不超过 500 个图元素；
- 预计超过 1,000 个图元素时阻止全量绘制并要求筛选；
- 不可变历史版本按 `revision_id` 缓存；
- 自动影响分析使用防抖和过期请求保护；
- 页面切换不得重复加载相同范围、相同版本的静态数据。

## 14. 前端验收标准

- [ ] 机台知识库只有“基础配置、模型构建、版本管理”三个二级页面。
- [ ] 工作顺序与现有建模流程一致。
- [ ] 三个页面共享唯一的范围选择栏。
- [ ] 草稿可以跨基础配置和模型构建保留。
- [ ] 版本管理不能任意修改模型。
- [ ] 历史版本只能只读打开。
- [ ] 恢复历史内容会创建新草稿和新版本。
- [ ] 对象改名显示为字段变化，身份和关系不变。
- [ ] 关系端点变化显示为删除旧关系和新增新关系。
- [ ] 部分回写明确显示主动选择项和必要依赖。
- [ ] 回写完成后明确说明原实例未改变。
- [ ] 实例升级失败不改变当前版本和冻结基线。
- [ ] 状态转移图只保留完整 `state_transition` 视图。
- [ ] 活动包只作为管理、引用和筛选入口，不显示为求解节点。
- [ ] Scope Guard、维护意图和虚拟活动不再出现在现行界面。
- [ ] 状态快照和临时求解条件不进入知识版本。
- [ ] 求解页只读取正式实例版本，不读取草稿。
- [ ] API 失败和并发冲突不会清空草稿。
- [ ] 大型树、差异列表和图满足本文件的性能基线。

## 15. 基线变更规则

本文档为 Frozen MVP 基线。后续若要改变二级页面数量、活动包求解边界、历史版本只读原则、草稿范围或回写/升级流程，必须：

1. 明确提出新的产品决策；
2. 同步检查后端设计基线；
3. 更新对应 TICKET；
4. 在本文档记录日期、原因和兼容影响。
