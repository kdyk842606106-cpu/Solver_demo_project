# 网络编辑器浏览器流程检视

> 日期：2026-06-24
> 入口：生产构建页面 `frontend/dist` + 本地 API 代理
> 检视对象：`数据管理 -> 网络编辑器`
> 演示机型：`NE Container 1782223554439 (NE_CONTAINER_1782223554439)`
> 说明：检视过程中临时创建了一条 `context_input` 绑定用于验证连接流程，结束前已删除。

## 1. 启动与访问结论

- 后端在 `127.0.0.1:8012` 可启动，网络编辑器 API 调用正常。
- 当前机器上 `8000`、`5173` 端口绑定被系统拒绝，Vite dev server 后台启动时出现 `esbuild spawn EPERM`。
- 为完成浏览器检视，新增本地工具 `scripts/serve_frontend_dist_proxy.py`，用于服务 `frontend/dist` 并把 `/api/*` 代理到后端；后续已纳入正式 `npm run preview:api`。
- 2026-06-24 已补强：`app/main.py` 的 `/` 优先服务 `frontend/dist/index.html` 和 `/assets/*`，没有生产构建时才回退到 `frontend/index.html`。

## 2. 已验证可用功能

### 2.1 页面入口与基础状态

- 前端生产构建页面可打开，顶部显示系统标题、版本和服务状态。
- `数据管理 -> 网络编辑器` 页签可进入。
- 未选择设备类型时，`新建状态`、`新建虚拟活动`、`新建原子活动`、`刷新`、`影响分析`、`校验`、`求解预检` 均禁用，并显示“先选择一个设备类型”。

### 2.2 设备类型加载

- 设备类型下拉能加载已有机型。
- 选择演示机型后，网络编辑器加载以下工作区：
  - 顶部视图模式：`纲要`、`实现`、`求解`。
  - 深度控制：`状态深度`、`活动深度`。
  - 总览指标：状态、活动、虚拟活动、可执行活动、绑定、深度、最长依赖链、覆盖缺口、部分实现虚拟活动、跨层级、孤立节点、阻塞。
  - 左侧资源树：状态树、活动树、原子活动叶子、未布置节点、状态引用。
  - 中间二部图画布：状态列、活动列、虚拟活动容器。
  - 右侧属性与绑定：当前选择、影响分析、创建绑定、绑定列表、覆盖刷新/删除。
  - 底部校验与求解预检。

### 2.3 画布交互与绑定

- 点击状态节点和虚拟活动节点后，右侧“当前选择”同步显示状态和活动。
- 快捷按钮会按活动类型变化：
  - 虚拟活动：`状态 -> 上下文`、`活动 -> 声明输出`。
  - 原子活动：`状态 -> 输入`、`活动 -> 产出`。
- 对虚拟活动执行 `状态 -> 上下文` 能把绑定加入编辑草稿，toast 显示“绑定创建已加入草稿”。
- 创建后节点摘要会同步更新，例如状态节点出现活动、状态包覆盖或绑定摘要，虚拟活动出现上下文输入摘要。
- 检视结束前已通过 API 删除本次新建的测试绑定。

### 2.4 原子活动展开

- 点击左侧活动树中的原子活动叶子，会自动定位画布中的可执行活动，并把活动展开到原子层。
- 可执行活动层显示原子活动节点，并用求解参与状态区分可执行活动和仅展示活动。
- 在缺少启用 `op_rule` 的情况下，点击快捷连线不会错误创建求解绑定；初次检视时提示为英文，2026-06-24 已补强为中文并指向活动能力/规则维护。

### 2.5 校验与定位

- 点击 `校验` 后能生成建模校验和求解器准备校验。
- 当前演示数据中：
  - 孤立状态/活动显示为 `info ORPHAN_STATE` / `ORPHAN_ACTIVITY`。
  - 原子活动缺输入、缺输出、缺规则显示为 `error EXECUTABLE_MISSING_INPUT`、`EXECUTABLE_MISSING_OUTPUT`、`EXECUTABLE_MISSING_RULE`。
  - 求解器准备状态变为 `blocked`。
- 点击 `EXECUTABLE_MISSING_RULE` 行的 `定位` 后，画布能定位并选中对应原子活动，toast 显示“已定位 + 活动编码”；规则类问题还提供 `规则` 动作，可跳转到 `活动能力` 页签补齐规则。

### 2.6 影响分析

- 选中原子活动后点击 `影响分析`，影响分析面板显示：
  - 直接前置状态、继承前置状态、产出状态、绑定数量。
  - `参与求解活动` 标识。
  - 所属虚拟活动：二级包和一级活动。
  - 相关 Issues。
- 相关状态、虚拟活动和原子活动会在画布高亮。

### 2.7 求解预检

- 点击 `求解预检` 后，在模型 blocked 时显示阻塞状态。
- 页面不再出现独立 JSON 下载或求解模板下载按钮；`/solve/layered` 区域只作为求解预检摘要展示。
- 求解预检能显示：
  - `Goal facts`
  - `Candidates`
  - `Rules`
  - 状态包聚合
  - 虚拟活动分组
  - `Blocking`
  - `/solve/layered` 必填运行时字段
  - 可执行活动表
  - Blocking issues

### 2.8 创建抽屉

- `状态` 抽屉包含：编码、名称、类型、所在状态包、排序、启用。
- `虚拟活动` 抽屉包含：编码、名称、层级、类型、排序、启用。
- `原子活动` 抽屉包含：编码、名称、所属活动包、类型、排序、启用。

### 2.9 求解视图

- 切换到 `求解` 视图后，画布只保留可执行活动，不把虚拟活动作为求解任务显示。
- 在当前缺输入/输出/规则场景下，求解视图显示 1 个 executable、3 个 blocking。

## 3. 需要改进或继续开发的点

### P0 / 启动与交付体验

- **生产入口需要修正**：已处理。`app/main.py` 优先服务 `frontend/dist/index.html` 和 `/assets/*`，没有生产构建时回退到 Vite 源码入口。
- **提供稳定本地预览命令**：已处理。`frontend/package.json` 新增 `npm run preview:api`，复用 `scripts/serve_frontend_dist_proxy.py` 服务 `frontend/dist` 并代理 `/api/*`。
- **端口策略需要可配置**：已处理。`preview:api` 可通过 `--backend` 和 `--port` 覆盖后端地址和前端端口，README 给出 8012/8013 示例。

### P1 / 建网操作引导

- **缺规则时的快捷绑定文案需要产品化**：已处理。缺启用规则时提示先去活动能力或规则维护创建并启用 `op_rule`；存在多条启用规则时提示在右侧规则下拉框明确选择。
- **已处理：原子活动规则创建入口缺失**：缺规则、规则无效或规则未明确选择的问题行现在提供 `规则` 动作，点击会先定位相关对象，再切换到 `活动能力` 页签维护或启用规则。
- **已处理：连接方式需要更显性**：画布动作条提示已改为按当前选择状态动态变化；无选择、只选状态、只选活动、状态+活动双选、预览模式和拖拽中都会给出不同下一步提示，并保留快捷连接按钮。

### P1 / 布局与可视性

- **已处理：720px 高度下右侧属性区和底部校验/求解预检明显被截断**：网络编辑器工作区已增加内部高度容器，左侧资源区、右侧属性区和底部校验 / 求解预检区各自滚动，画布在中间区域内伸缩。
- **已处理：设备类型下拉数据噪声较多**：设备类型选择器保留搜索，并按 `最近使用`、`业务设备类型`、`测试 / 样例设备类型` 分组展示；切换机型会记录最近 5 个使用项。
- **已处理：求解视图只剩原子活动时容易误以为状态消失是错误**：求解视图画布顶部新增状态提示，说明该视图仅显示可执行活动与求解事实投影，虚拟活动作为分组元数据保留在求解预检中。

### P1 / 无障碍与自动化稳定性

- **已处理：Element Plus segmented 的 radio 是隐藏元素**：视图模式、绑定覆盖、状态类型、活动层级和原子活动产出覆盖分段控件已补 `data-testid` 与 `aria-label`，浏览器自动化可直接定位分段控件后点击可见分段文本。
- **已处理：隐藏抽屉 DOM 会污染文本抽取**：状态、虚拟活动、原子活动抽屉，以及重复状态、共享状态包修改、批量绑定弹窗均已启用 `destroy-on-close`，关闭后不再保留隐藏表单 DOM。
- **已处理：多个同名按钮需要测试标识**：顶部工具栏、资源区、画布、属性区、问题表、抽屉/弹窗按钮和画布节点/容器已补 `data-testid`，问题表定位/刷新按钮还携带 `data-issue-code` 便于按问题类型筛选。

### P2 / 性能与请求

- **已处理：初始加载存在重复 `GET /api/v1/machine-types`**：前端 `getMachineTypes` 已在 API 层增加共享缓存和 in-flight 请求合并；创建、更新、删除设备类型后会清空缓存，避免后续页面读取旧列表。
- **已处理：切换/定位会触发多次 graph/impact 请求**：网络编辑器影响分析自动刷新已增加短防抖和请求序号保护，快速切换选择时旧响应不会覆盖新焦点；手动点击 `影响分析` 仍立即请求。

### P2 / 文案一致性

- **已处理：初次检视时中英混合较多**：当前核心 UI、节点摘要、快捷连线、深度控制、问题定位按钮和绑定提示已分批中文化；仅保留 issue code、role、`op_rule` 等必要技术字段作为次级排查信息。
- 2026-06-25 继续清理残留兜底：右侧状态详情空归属从 `Root` 改为 `未加入状态包`，网络编辑器加载失败兜底从 `Load network editor data failed` 改为中文提示。
- 2026-06-25 继续清理问题建议兜底：问题表和提交前复核优先按 issue code 显示中文建议；未知 code 不再直接透出后端英文 `suggested_action`，而是使用中文通用建议，后端字段仅保留为接口协议和排查信息。
