# Planner 适配实施说明

## 1. 实施结论

本分支以 `planner-shared-scenario/v1` 为唯一的新场景写模型，前端只提供“Planner 数据”和“多引擎求解”两个入口。旧机台分层数据继续只读保留，必须经迁移预览后才能转换为新场景。

已落地能力：

- 活动、基础状态、资源、事件、活动包及成员内部身份全部由后端创建；
- 活动创建时自动创建一个主完成状态，活动包创建时自动创建同 UUID 后缀的隐藏状态包；
- 活动包固定两级，活动可在多个二级包中复用，镜像状态成员同步复用；
- 网络编辑器复用原 `NetworkEditorX6Canvas` 的缩放、拖动、容器和连线呈现；适配器只投影活动节点，活动包为容器，状态/状态包不进入画布 DOM；
- 拖动、活动连线和移除依赖先进入页面草稿，一次事务统一提交；
- 已有活动可在数据页编辑名称、工期、最大执行次数、前置状态和外部事件，活动身份保持不变并与网络连线草稿合并提交；
- “多引擎求解”按次选择当前状态与目标状态，不回写场景；`LEGACY`、`ASTAR`、`GA` 和 `ALL` 使用同一有效快照，结果统一交给 Planner Validator 重放；
- JSON、中文 Excel 以及旧分层数据迁移均经过同一个规范化和校验入口。

## 2. 运行配置

后端通过 `PLANNER_PROJECT_PATH` 定位 Planner 源码，默认查找 Solver 项目同级的 `planner` 目录。

```env
PLANNER_PROJECT_PATH=D:\planner
```

数据库头升级为 `017_planner_runtime_state_targets`。本迁移不新增业务表或字段，只把历史目标活动/目标包转换为建议目标状态，并在场景 `provenance.runtime_state_target_migration_v1` 中保留降级恢复信息。

既有表保持不变：

- `planner_scenario`：权威场景 JSON、内部并发序号和下一展示编号；
- `planner_run`：求解请求、不可变快照哈希和统一结果。

`015_knowledge_repository` 在本分支中仅作为无操作兼容标记，用来识别曾经运行过旧知识库版本的数据库；不会创建、读取或删除知识库结构。

## 3. 用户工作流

1. 新建或导入场景；
2. 进入编辑，建立一级/二级活动包；
3. 建立基础状态和活动，活动编号及运行所需内部状态由系统产生；
4. 将活动加入二级包，或在活动网络中拖动、连接活动；
5. 统一提交草稿并执行场景预检；
6. 到“多引擎求解”选择当前状态、目标状态和引擎；
7. 启动求解；选择只进入本次运行记录，不修改场景修订号。

选择场景时，当前状态默认取 `initial_state_ids`，目标状态默认取 `goal_state_ids`；“恢复建议值”只重置页面选择。普通页面只显示状态业务名称，同名状态追加短序号，不展示来源活动或内部 ID。完整 JSON 回导可以选择保留合法 ID；普通 JSON/Excel 导入会重新生成身份并重写引用。

## 4. 本期边界

本期资源采用“容量汇总”模型。例如“技术员容量 3”只表示任一时刻最多可同时占用 3 个单位，不回答具体由张三、李四还是某台设备执行。

“资源实例”是容量背后的具体可指派对象，通常还带有人员资质、设备型号、班次日历、位置、可用性、切换成本和任务绑定。支持它需要三种引擎同时增加实例选择变量、排他约束、日历与结果指派语义；否则同一场景在不同引擎会产生不同含义。因此本期明确不进入，接口能力响应为 `resource_instances_supported: false`。

同时不进入本期：知识库版本管理、工作日历、数值效果、消耗物料、抢占以及实例级资源调度。导入或迁移发现这些内容时必须阻断或形成明确报告，不能静默降级。
